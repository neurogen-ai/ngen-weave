# Step 9 — human node executor, review artifacts, resume

PRD reference: "Human nodes" section.

## Goals

- HumanExecutor that writes a review artifact and halts the run in `waiting_human`; file-based resume when `<node-name>.reviewed.yaml` appears; route selection via the shared expression evaluator.

## Detailed steps

1. Artifact writer. On activation write `.loom/runs/<run-id>/reviews/<node-name>.yaml`:
   - `node`: name; `run_id`; `created_at`.
   - `input`: the node's validated input data (context for the reviewer).
   - `fields`: one entry per property in the output schema — name, type (from schema), required flag, current value (empty).
   - `decision` guidance: if the schema declares an enum field named `decision`, list allowed values as a comment.
2. Executor returns `{ next: {kind:"wait"} }`; engine sets node status `waiting_human`, run status `waiting_human`, persists state, halts.
3. Resume path. `resumeRun` checks: if run status is `waiting_human` and `<node-name>.reviewed.yaml` exists:
   - Parse it; validate the filled fields against the node's output schema with Ajv. Missing required fields → keep waiting, log which fields are missing (do not crash).
   - Evaluate routes in declared order against bindings = filled field values (+ params). First matching `when` wins; fall through to the default route (no `when`) if present; no match and no default → data failure report on the run.
   - Mark artifact consumed (state records the decision), set node done, continue stepping.
4. `loom status`-friendly info: state.json already carries what's needed; nothing extra here.
5. Extend step 4's validator: compile human route expressions with allowed identifiers = output-schema properties.

## Success criteria

- A run reaching a human node writes a complete artifact and stops; filling the reviewed file and running resume continues along the routed edge.

## Tests

- Artifact contains input context and all schema fields including enum hint.
- Reviewed artifact with all required fields resumes and routes to the approve target; reject case routes to its target.
- Default route used when no `when` matches.
- Missing required field in reviewed file → run stays waiting, clear message.
- Route expression referencing unknown field fails at validate time (step 4 integration).

## Commits
- `feat(nodes): human executor with review artifact contract`
- `feat(engine): resume from completed human review via route table`

## Out of scope
- Any UI/CLI interactive prompting (the file contract is the interface)
- JSON form of the artifact (v0.2 note), notifications, timeouts on reviews
- Multiple pending human nodes per run (sequential engine means at most one)
