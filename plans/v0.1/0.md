## Conventions every step follows

- Single npm package at repo root (`agent-loom`). No monorepo.
- Layout: `src/schema`, `src/engine`, `src/cli`. Tests in `src/**/*.test.ts` next to the code, plus `test/e2e` for end-to-end.
- Every structure described in the PRD gets a Zod schema in `src/schema`. The Zod schema is the single source of truth; types are inferred from it with `z.infer`.
- Paths inside a workflow resolve relative to the file that declares them. Resolve once at load time; after loading, everything is absolute or workflow-root-relative.
- All errors use a small typed error hierarchy: `ConfigError` (malformed workflow, static), `DataError` (schema-invalid node output, flows through the graph), `InfraError` (transport/API, retryable). Defined once in step 2 and reused everywhere.
- Commit style: conventional commits, one commit per "Commit" bullet in each step file.
- Test runner: vitest. Every step's tests must pass before committing.

## Rules for the implementing agent

- Do exactly what the current step says. If you notice something the PRD needs but the step doesn't ask for, it is almost certainly listed under that step's "Out of scope". Leave it.
- Never invent features beyond the PRD. When in doubt, re-read the PRD section cited at the top of the step.
- Keep abstractions narrow: one interface per boundary (engine, model adapter, evaluator). No plugin systems, no options objects with more than a handful of fields.
- If a step's success criteria cannot be met because an earlier step missed something, stop, fix the earlier step minimally, note the fix in the commit message, and continue.

## Global out of scope (applies to all steps)

These are v0.1 non-goals per the PRD. Reject any temptation to add them:

- Parallel execution of any kind
- Subworkflows / nested graphs (only the contract invariant is validated, in step 4)
- Web UI, HTTP server, MCP exposure
- SQL observer queries; template interpolation inside expressions
- Inline JSON Schemas (external files only)
- Token streaming; multi-workflow scheduling; secrets beyond env vars
- Worker output retry logic (control nodes + observers own quality policy)
