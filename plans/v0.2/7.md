# Step 7 — `loom export`, serving config, CI generation

PRD reference: "Execution" section (export as build artifact, self-hosted langgraph-server, deployment docs).

## Goals

- The `loom export <workflow-dir>` CLI command exists and CI generates and commits `langgraph/`. A generated project is servable by self-hosted langgraph-server with no hand edits.

## Detailed steps

1. `packages/export-langgraph` exports one function: `exportWorkflow(validatedGraph, outDir): ExportResult` (files written, plus any warnings). Idempotent: clears the workflow's subdirectory before writing.
2. `packages/cli`: add `loom export [workflow-dir...]` — validates first (reuse v0.1 validate path), then exports. No workflow arg means all directories listed in the project manifest if present, else `workflows/*` containing a graph.yaml. Print a summary table of exported workflows.
3. Emit `langgraph.json` per project root (not per workflow): entries for each workflow graph, pointing at `<name>/graph.py`, plus checkpointer config. This file is what `langgraph-server` consumes.
4. Add `langgraph/README.md` (generated): "built by CI from workflows/, do not edit" plus regeneration instructions.
5. Python toolchain for CI: add `packages/export-langgraph/python-tests/requirements.txt` (pinned langgraph/langchain/litellm versions) and document local setup (`uv` or pip) in the root README.
6. GitHub Actions workflow `.github/workflows/export.yml`: on push touching `workflows/**` or the compiler — run vitest, run pytest, run `loom export`, commit regenerated `langgraph/` if diff exists (actions-style bot commit), fail if manual edits to `langgraph/` are detected that regeneration would overwrite (the diff-commit approach handles this naturally).
7. Deployment docs: `docs/serving.md` covering how to start self-hosted langgraph-server against the generated `langgraph.json`, env vars needed (`LOOM_DB`, model provider keys). Short; the server is not our deliverable.

## Success criteria

- `npm run build && loom export` regenerates `langgraph/` byte-identical to the committed version.
- `langgraph-server --config langgraph/langgraph.json` (or the documented equivalent command) serves the example workflow locally.

## Tests

- CLI integration test: export example → snapshot directory tree → export again → byte-identical.
- Test that exporting after editing graph.yaml changes output (staleness detection sanity).
- CI config reviewed by inspection only.

## Commits
- `feat(cli): loom export command`
- `feat(export): langgraph.json server config`
- `ci: regenerate committed langgraph/ artifacts on workflow changes`

## Out of scope
- Hosting or shipping langgraph-server itself
- Watching filesystems / auto-export on save
- Incremental export of single nodes; always full workflow regeneration
- Docker images, remote deployment automation (docs only)
