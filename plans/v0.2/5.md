# Step 5 — exporter: graph skeleton

PRD reference: "Execution" section and the compilation map; "Workflow-as-tool" (nothing here — MCP is step 10).

## Goals

- `packages/export-langgraph` compiles a validated workflow into a runnable Python LangGraph project: worker nodes, control-node conditional edges, fan-in state assembly. Observers, humans, artifacts come in step 6; this step proves the skeleton.

## Detailed steps

1. Package structure: `src/compiler.ts` (workflow AST → intermediate plan), `src/emit.ts` (plan → Python file text), `src/templates/` (string templates for generated files). Keep templates as plain TS template strings, no template engine.
2. Output layout per workflow, written under `<projectRoot>/langgraph/<workflow-name>/`:
   ```
   graph.py          # StateGraph construction
   nodes/*.py        # one module per node
   state.py          # TypedDict state schema
   schemas/*.json    # copied input/output schemas
   pyproject.toml    # deps: langgraph, langchain, litellm
   langgraph.json    # server config (filled in step 7)
   ```
3. State design (`state.py`): a single `TypedDict` with `messages`-free flat keys — one key per node output plus `run_id`, `step_count`, and an `inputs` dict holding fan-in assembled values. Simple beats clever; every node reads its declared inputs from `inputs`, writes its output under its own name.
4. Worker node → generated async function:
   - Reads its input fields from state (fan-in map applied at entry: the function assembles `inputs` from the named parent outputs before validation).
   - Validates input against the copied JSON Schema.
   - Calls the model via `langchain.init_chat_model(model_id, provider_provider=..., ...)`, applying variant reasoning effort.
   - Validates output against the output schema; invalid output raises a typed `DataError` exception class defined in a shared generated `_runtime.py`.
5. Control node:
   - `mode: programmatic` → emit the checks as plain Python conditionals over the input using the same expression semantics as v0.1's evaluator (transpile the sandboxed JS expression subset to Python: identifiers, comparisons, boolean ops only; anything outside the subset is a compile error reported back, not silently cut).
   - `mode: model` → like worker but prompt requires the `pass` boolean.
   - Emits conditional edges: `add_conditional_edges(name, router_fn, {pass_target, fail_target})`.
6. Fan-in: child node's declared `inputs:` map becomes explicit dict assembly in the emitted function preamble. Missing parent output → clear KeyError naming the edge.
7. `max_steps` → a counter checked at each node entry; exceeded raises `BudgetExceeded`.
8. Compiler takes the already-validated graph object from `@agent-loom/core` (never re-parses YAML). If compilation cannot proceed, it throws with workflow-relative location info.
9. Add a pytest suite under `packages/export-langgraph/python-tests/` that runs the generated project in-process with a memory checkpointer and a fake chat model (langchain test doubles). CI runs vitest + pytest.

## Success criteria

- Exporting the draft-review example produces a project where `graph.compile().invoke(...)` runs draft → quality_gate → finalize with fake models, no human node needed yet.
- Generated code is deterministic: same input, byte-identical output (snapshot test).

## Tests

- Snapshot tests of generated Python for: simple chain, control branch both directions, fan-in map assembly, max_steps exhaustion.
- Pytest integration: run exported example graph end-to-end with fake model; assert final state contains finalize output.

## Commits

- `feat(export): compile workers, control edges, fan-in to LangGraph Python`
- `test(export): snapshot and pytest coverage for skeleton compilation`

## Out of scope

- Human nodes / interrupt() (step 6)
- Observer wrappers (step 6)
- Artifacts sink (step 6)
- Checkpointer selection, serving config (step 7)
- Events emission (step 8)
- Parallel branches, subgraphs, any LangGraph feature beyond what the map needs
