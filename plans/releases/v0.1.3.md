# ngen-weave v0.1.3 release requirements

Status: draft
Prerequisite: plans/releases/v0.1.md complete.

## The principle

Added to the PRD beside the no-overwrite invariant:

> Prompt-visible content is fully determined by declared structure: what reaches a node's prompt depends only on declared wiring, schemas, and declared ordering — never on runtime scheduling, arrival order, or execution timing.

This subsumes no-overwrite and extends it to ordering. Sequential execution makes it true today; this release keeps it true and makes the ordering contract explicit instead of accidental.

## The gap

Collected fan-in assembles parent outputs as `[state[src] for src in sources]` where sources follow `g.add_edge()` declaration order (`runner.py` `_assembly_plan`/`_assemble_input`). Deterministic across runs and resume, but contractual-by-accident: no author-facing way to control sequence, nothing documented, no test pinning it. Slots are unaffected (per-field keyed, exactly-once coverage); dispatch and single-parent forms are singleton inputs.

## The mechanism

Optional child-side declaration on the collector:

```python
class ReduceInput(BaseModel):
    reviews: list[ReviewOut] = Field(min_length=2, max_length=5)


class Synthesize(Workflow):
    input_type = ReduceInput
    collect_order = "score"  # dotted path into each element's output dump
```

- Assembly stable-sorts the collected list by that key; ties resolve by edge-declaration order (deterministic, resume-safe).
- Unset means declaration order — promoted from accident to documented contract.
- Import-time check: the path must resolve against every parent's `output_type`; violations name the offending parent class.
- Edge-level positionals (`into="reviews[0]"`) and source-side ordinal fields were considered and rejected: they overload slot semantics or pollute parents' schemas with a consumer concern. Templates render each entry; they never decide entry sequence ("templates stay data").

## Tests

The information-preservation e2e lands with this release (partially pre-landed):

1. K parents feed a collector whose prompt renders every input; each parent's canned reply embeds a unique marker string.
2. Assert every marker appears exactly once in the recorded `model_call` payload — catches silent context loss at any wiring depth (the code_review gate-bug class).
3. Assert markers appear in declaration order — pins the default contract.
4. With `collect_order` set, markers appear in sorted order — pins the knob.
5. Kill-and-resume mid-run reproduces byte-identical prompts — pins determinism across checkpoints.
