# ngen-weave v0.6 release requirements

Prerequisite: plans/releases/v0.5.md complete (plugins, notification reference plugins, boxed autonomy).

## What v0.6 adds

The platform layer ngen-weave has been running without: a real database behind the existing store seams, and nothing else. Until now everything lived in files under `.ngen-weave/`, which was honest and simple and stops being enough once long-lived server deployments exist. Auth, roles, and the collaboration slice that needs authenticated principals are v0.8; the database lands alone here so the storage migration is never entangled with identity work.

## Postgres becomes canonical

- Migration of run state, events/provenance records, artifact manifests, and workflow registrations into Postgres.
- SQLAlchemy 2.0 async engine, Alembic migrations from day one. Schema churn is guaranteed through 1.0; migration tooling pays immediately.
- Artifact blobs stay content-addressed on disk or object storage; the database holds their hashes and manifests. Hashes are the join key.
- JSON export stays a first-class operation, not an afterthought: any run exports to the same single-file JSON format used before v0.6, byte-compatible with the pre-DB writer where practical. Reproducibility handoffs never require database access.
- SQLite remains the zero-config local mode (`ngen-weave run` on a laptop still touches no server). The database is required only in server deployments.

## Non-goals

- Token auth, roles, multi-reviewer human nodes, tickets, `import-project`: v0.8, where auth gives them principals to attach to.
- Multi-tenancy beyond projects-per-user.
- SSO/OIDC federation.
- Live collaborative editing (post-1.0).
- Distributed execution (1.1).

## Success criteria

1. A fresh server deployment runs against empty Postgres with Alembic up-migrations only; no manual schema steps.
2. Any run in either backend exports to the pre-v0.6 single-file run-JSON shape through one shared writer, with file-mode output unchanged byte for byte.
3. File mode survives untouched as the default: `ngen-weave run` with no database config behaves exactly as v0.5.
