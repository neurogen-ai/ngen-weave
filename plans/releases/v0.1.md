# ngen-weave v0.1 release requirements

Status: draft
Prerequisite: none. First version.
Scope: the Python core. Everything here is testable as a vertical slice: define a workflow in Python, configure it in YAML, run it locally on LangGraph, resume it after a crash or human pause.

## What v0.1 delivers

The Workflow abstraction, done right once so nothing later reworks it:

- A single `Workflow` class family (no generics). Subclasses declare `input_type` and `output_type` as pydantic models, validated strictly at every boundary. The same classes generate the JSON Schema consumed by config, validation, and later MCP/UI.
- Composite workflows declare structure as class attributes: `children`, `edges`, and per-target `inputs` fan-in maps (a target with multiple parents must map every required input field; incomplete maps fail at validate time). Example:

```python
@workflow("code_review")
class CodeReview(Workflow):
    input_type = ReviewRequest
    output_type = ReviewedDiff
    children = [draft, gate, human_review, finalize]
    edges = [(draft, gate),
             (gate, finalize, "pass"),      # control edges name their branch
             (gate, human_review, "fail")]
    inputs = {finalize: {"review": human_review}}   # fan-in map on the target
```

The YAML config mirrors these attributes directly: workflows by registered name, kwargs for parameters, the same edge and fan-in shapes.
- Worker prompts are a `prompt` class attribute: a template string rendered against validated input fields (`{request.diff}`), overridable by a `prompt(self, input)` method when generation needs logic. Templates stay data so they serialize, diff, and render in UIs.
- Human workflows take one edge input and surface it as read-only `context` in their review artifact. Between input and output sits an internal state model (`state_type`, a pydantic model): editable, prefilled from the context, validated on submission. Edges out of a human carry branch labels matched against submitted state values (an enum verdict like `"approve"` / `"reject"` / `"revise"` generalizes control's pass/fail), so routing reads what the human submitted without a mandatory downstream control node. The artifact therefore has two sections:

```yaml
context:  {...}     # edge input, validated against input_type, never edited
response: {...}     # empty editable slots generated from state_type leaves
```

Response slots cover leaf primitive fields of `state_type` (str/int/bool/enum/literal); nested models expand recursively into further slots; fields with defaults may be left empty; required-without-default blocks completion. Completing a review validates with plain `state_type.model_validate(response)`; out-edge branch labels must then match the submitted state values, resolved the way control branch labels are.

A per-node `prefill` map seeds response slot values from the context: path strings into the edge input (`"gate.notes"`) primarily, callables where derivation needs logic. Prefill fills the artifact, never completes it: even fully prefilled required fields wait for human submission, since submitting the reviewed artifact is the act that resumes the run.
- Node types: Worker (model call via LiteLLM), Control (programmatic predicate or model-filled boolean `pass`, routing on pass/fail targets), Human (interrupt plus review artifact plus state-driven enum routing). All four are Workflows.
- Recursion native from day one: a workflow appears anywhere a node does. Even if tests exercise one level of nesting deeply and two levels lightly, checkpoint trees, per-level cost attribution, interrupt propagation, and `(run_id, node_path)` addressing exist now.
- Observers attached to any workflow, constructed with a predicate function over the frozen six-field metadata object (iterations, tokens_in_context, tokens_total, cost_usd, elapsed_ms, last_output_valid) plus a required description string serving as the serializable copy of the expression; actions are pause/stop/reroute. Metadata surface frozen for v0.1.
- Provenance records emitted on every activation without opt-in: kind-typed payloads (node_activation, model_call, artifact_write, observer_firing) in a versioned envelope.
- AgentNode seam declared with mocked executor and PermissionSet shape, so budgets and boxes have something real to constrain later.

## Registration and configuration

- The `@workflow("name")` decorator marks workflow classes at import time and carries description metadata.
- A generator step scans declared packages and emits an entry-point manifest shipped with the distribution; the loader reads entry points; a stale-manifest hash mismatch fails loudly at startup.
- Author-facing YAML config names registered workflows with kwargs (JSON accepted as equivalent dialect). Thin by design: wiring, parameters, run settings. One standing constraint recorded here so early configs never paint us into a corner: the v0.4 editor serialization widens this same format to cover every serializable field, never a new syntax. Everything valid in v0.1 configs stays valid forever.

## Engine and state

Thin wrapper over LangGraph's StateGraph: nodes are node functions, control booleans are conditional edges, human interrupts map to `interrupt()`, observer actions translate to `Command(goto=...)`, `interrupt()`, or `END`, composites are subgraphs.

Sequential execution only. Fan-in requires explicit total maps when a node has multiple parents; incomplete maps fail at validate time. SQLite checkpointer by default, memory for tests. One JSON file per run under `.ngen-weave/runs/<run-id>/` holding metadata plus the event/provenance stream, written atomically per transition, always valid, sufficient to re-run.

Error taxonomy: data failures (schema-invalid output, failed control logic) flow through the graph and never retry; infra failures retry per policy (default 3 attempts, exponential backoff from 1000ms); config errors kill the run with a report. `ngen-weave resume <run-id>` continues from any stop.

## Model layer

LiteLLM via `init_chat_model`, resolved through project-root `models.json` shared across workflows. Variants are data; node-level variant overrides defaultVariant. Auth is provider environment variables. One `CompletionProvider` protocol; adapters translate, never extend.

## Artifacts (minimal)

A workflow may declare outputs worth persisting; validated writes land content-addressed under `.ngen-weave/projects/<project>/` with provenance linking artifact to producing activation and input hashes. Diff tracking, display, export formats come later; the record shape is fixed now.

## CLI

```
ngen-weave generate-manifest <package>     # scan + emit entry-point manifest
ngen-weave validate <config-or-module>
ngen-weave run <workflow> [-i input.json]
ngen-weave resume <run-id>
ngen-weave status <run-id>
```

Every command also ships under the short alias `ngw` (`ngw run`, `ngw resume`, ...), registered as a second console script entry point in the same package. Both names are official; docs use the long form, examples may use either.

Validation catches: schemas resolve, names unique, edges reference existing children, fan-in maps complete, control schemas require boolean `pass`, human out-edge branch labels match declared state values, workflow contracts agree with entry/exit nodes, manifests fresh, observer declarations valid (description non-empty, actions and reroute targets resolvable; predicates are user code, we validate the declaration, not the body).

## Repo and toolchain

uv workspace monorepo, packages `ngen-weave-core` and `ngen-weave-cli` shipping inside one `ngen-weave` distribution. Python ≥3.12, pytest, ruff, Apache-2.0, Forgejo CI, conventional commits.

## Canonical examples

Two shipped, both exercised end to end by tests:

1. **Code review** (canonical): worker drafts a review, control gates it, human approves or rejects, reviewed diff lands as an artifact with provenance.
2. **Document drafting**: draft, quality-gate, human review, finalize, with an observer rerouting on max tokens. Kept visible so agnosticism stays honest.

## Non-goals for v0.1

- Parallel execution, scheduling, queues.
- MCP exposure, serving, web UI, run management API.
- Artifact diffing, display, export.
- Plugins beyond in-process subclassing.
- Real AgentNode execution (mocked only).
- Postgres or auth (files and SQLite only).

## Success criteria

1. Both canonical examples run end to end from the CLI and pass e2e tests, configured through YAML without touching their source.
2. Killing the process mid-run and calling `ngen-weave resume` completes the run correctly.
3. A two-level nested workflow runs with correct cost attribution to the parent observer and a resumable interrupt at depth 2.
4. Every activation produces provenance addressable by `(run_id, node_path)` with zero logging code written by the workflow author.
5. Renaming a workflow class without regenerating the manifest makes `ngen-weave validate` fail with a clear staleness error.
