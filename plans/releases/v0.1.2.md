> Patch release making provider failures loud and helpful on the first attempt instead of silent and cryptic after three retries. Scope is strictly the fail-fast classification plus its error message; no features.

# ngen-weave v0.1.2 release requirements

Status: draft
Prerequisite: plans/releases/v0.1.md complete.

## The problem

A first run against a real provider fails unhelpfully when auth or the endpoint is wrong. Today `LiteLLMProvider.complete` wraps every transport exception as retryable `InfraError`, so a missing `OPENAI_API_KEY` produces: three identical LiteLLM tracebacks (one per retry, ~seconds of backoff between), then `status failed` with no hint that an env var would fix it. The engine behaved correctly; the failure class is just misclassified.

## The mechanism

Classify at the boundary in `packages/ngen-weave-core/src/ngen_weave/models/provider.py` (`LiteLLMProvider.complete`), where the raw litellm exception is already in hand:

1. Inspect the caught exception for litellm's auth/connectivity exception types (`litellm.exceptions.AuthenticationError`, `NotFoundError` for unknown model/endpoint, `APIConnectionError`). These are deterministic: retrying cannot help.
2. Raise them as non-retryable `DataError`-class config failures (or a new `ProviderError(ConfigError)` sibling if a distinct type reads better) carrying a message that names the variant and the likely fix:

```
model call failed for variant 'example-model': authentication rejected by provider.
Set OPENAI_API_KEY (see models.json), or point the variant at a local server
with api_base (e.g. http://localhost:8080/v1).
```

3. Everything else stays `InfraError` and keeps the existing retry policy. Timeouts and rate limits remain retryable; only provable-permanent conditions skip the retries.

The CLI needs no change: it already prints `error: <message>` and exits 1 on `NgWeaveError`. The one-line improvement there is printing only the final message, never per-attempt tracebacks — litellm's own stderr noise should be suppressed inside `complete` (the message carries what matters).

## Tests

1. Unit: FakeProvider-style test asserting an `AuthenticationError` raised by a stubbed `litellm.acompletion` surfaces as the non-retryable error with the variant name and remediation text, with exactly **no** retry attempts (patch the engine's backoff sleep counter).
2. Unit: a generic `APIError` still retries 3 times then fails, unchanged.
3. e2e (optional): CLI run with a bogus key exits 1 with the remediation message on stderr, once.

## Acceptance

- [ ] Auth/connection/model-not-found failures abort on first attempt with a message naming the variant and the fix; no litellm traceback spam.
- [ ] Transient failures keep the existing 3-attempt exponential-backoff policy.
- [ ] Full suite green via `scripts/check.sh`; no public API change beyond the new error surface.
