# ngen-weave v0.7 release requirements

Status: draft
Prerequisite: plans/releases/v0.6.md complete (Postgres canonical store).

## What v0.7 adds

Consolidation before 1.0: removing what the platform outgrew, landing the one deferred small feature, and paying down debt so 1.0 is purely deployment and hardening.

## Retire the langgraph-server adapter

The adapter shipped in v0.2 to keep development testable while the serving layer moved, per the decision to keep both RunService implementations through v0.6. With Postgres-backed serving stable, this version deletes it:

- Remove `LanggraphServerService`, its config types, MockTransport fakes, and live-marked tests.
- De-parameterize the shared conformance suite down to the FastAPI implementation; the suite itself stays as the executable spec of run semantics.
- The serving-evidence design doc gets a closing entry recording why the removal happened now.
- langgraph-server remains usable behind RunService by anyone who wants it (the protocol seam is public); ngen-weave no longer ships or tests an adapter.

## External document links

Nodes may reference externally-hosted documents (Google Docs etc.) by link. ngen-weave tracks the link, not the content; provenance and versioning of external documents belong to the external provider. Deferred from v0.5 because it is a leaf feature that never justified holding up the plugin release.

## Cleanup

Debt accumulated across v0.5–v0.7 lands here: anything the platform migration left half-migrated, docs lagging the new database surfaces, deprecations flagged for 1.0's semver freeze. Named at implementation time, not speculatively.

## Non-goals

- Scheduling/cron parity (waits for demand).
- Simultaneous editing, workspaces (1.2).
- Anything new: this version's value is subtraction.

## Success criteria

1. The distribution neither depends on nor mentions langgraph-server as a shipped backend; the conformance suite runs green against the FastAPI implementation alone.
2. A node referencing an external document validates, renders in UI detail views, and appears in provenance as a link with no content claims.
3. No known-deprecated surface survives into 1.0 without an explicit decision record.
