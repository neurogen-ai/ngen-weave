## The bug

`packages/ngen-weave-core/src/ngen_weave/engine/runner.py`, in `Engine._compile_uncached`: the method receives `key` from `compile()` — computed as `(root_path, sorted models items, outer_scopes class paths)` — but ignores it and recomputes `(root_path, tuple(sorted(models.items())))`, dropping `outer_scopes`. It then consults and populates the same shared cache map (`self._compiled`) that `compile()` keyed with the full tuple.

Consequence: two compilations of the same workflow class under different outer scopes (i.e. different model-variant resolution chains from nesting) collide on the second lookup. The caller asks for scope A's graph, gets scope B's cached one — variant bindings frozen into checkpoints are wrong for that activation path. This is exactly the class of silent durability defect the engine exists to prevent.

## The fix

Delete the recomputation. `_compile_uncached` already receives `key` as a parameter; use it:

```python
    def _compile_uncached(
        self, wf: type[Workflow], models: dict, outer_scopes: tuple, key: tuple
    ) -> CompiledGraph:
        root_path = workflow_class_path(wf)
        # key already includes root_path, model variants, and outer scopes;
        # recomputing it here without outer_scopes caused cross-scope collisions.
        cached = self._compiled.get(key)
        if cached is not None:
            return cached
        ...
```

The defensive re-check inside `_compile_uncached` is also redundant: `compile()` is the only caller and has just missed on the same map under the same lock-free `_compiling` guard, so after using the passed-in `key` the early return there can be dropped too — keep it only if the recursion path for nested composites re-enters through `_compile_uncached` directly (verify while editing; if children are compiled via recursive `compile()` calls, drop it).

## Regression test

Add to `test_engine.py` (or a focused `test_compile_cache.py`):

1. Declare one composite `Outer` wiring a single `Worker` child, with two distinct model-variant overrides supplied via different `models` dicts per compilation.
2. Compile the same child class twice through two different outer scopes such that the resolved variant for the child differs between scopes.
3. Assert the two returned `CompiledGraph` objects differ (distinct variant binding for the child node), i.e. the second compile did not return the first scope's cache entry.
4. Conversely assert identity caching still works: compiling the identical `(class, models, outer_scopes)` twice returns the *same* object.

Run via `scripts/check.sh`; all 188 existing tests must stay green.
