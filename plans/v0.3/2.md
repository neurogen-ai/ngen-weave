# Step 2 — content hashing + workflow discovery

PRD reference: "Which workflows are exposed", "Data freshness".

## Goals

- One core module that (a) discovers workflows from a project root, via `loom.json` manifest or convention scan, and (b) computes a stable content hash per workflow. Both the web API and any future consumer reuse it. This is the module that makes "list all workflows with validity" a one-call operation.

## Detailed steps

1. New file `packages/core/src/discovery.ts`:

   ```ts
   export interface DiscoveredWorkflow {
     name: string;            // graph.yaml name
     dir: string;             // absolute workflow dir
     valid: boolean;
     errors: string[];        // validation error list when invalid
     hash: string;            // sha256 hex of dir contents
   }

   export function discoverWorkflows(projectRoot: string): DiscoveredWorkflow[];
   ```

2. Discovery order: if `<projectRoot>/loom.json` exists, load it via core's existing manifest loader (added in v0.2 step 10) and use its listed dirs. Otherwise scan `<projectRoot>/workflows/*/graph.yaml`. Both paths end in the same validate call.
3. **Invalid workflows appear in the list, marked invalid**, with the full validation error strings in `errors`. Wrap validation per-workflow so one broken workflow does not abort discovery of siblings. Invalid workflows get their name from the directory name (graph.yaml may be unparseable); do not attempt best-effort parsing of the rest of the structure.
4. Content hash: sha256 over, for every file under the workflow dir recursively, sorted by relative path: the relative path bytes followed by the file bytes. Deterministic across machines and runs. Implementation sketch:
   ```ts
   const h = createHash('sha256');
   for (const f of filesSortedByRelPath) { h.update(relPath); h.update(await readFile(f)); }
   ```
5. Add `computeWorkflowHash(dir)` as its own exported function — step 4 reuses it standalone for the schema endpoint.

## Tests

- Fixture tree with two valid workflows and one invalid: discovery returns three entries, correct names, `valid` flags, non-empty `errors` on the broken one.
- Manifest path and convention path return identical results for the same fixture.
- Hash stability: same content → same hash; changing one byte in any file → different hash; adding/removing a file → different hash; renaming a file → different hash (proves path is hashed).
- A workflow dir containing a subdirectory and dotfiles hashes without error.

## Out of scope (tempting, do not build)

- File watching or cache invalidation. The client polls and compares hashes; the server recomputes per request. Localhost disk reads are cheap at this scale.
- Caching parsed graphs keyed by hash inside the server process. Add only if profiling ever says so.
- Glob patterns or ignore lists in `loom.json`. The manifest format is fixed by v0.2; do not extend it.
- Returning parsed graph structures from discovery. It returns names, validity, errors, hashes only; full parsing lives behind the detail endpoint (step 4).
- Nested workflow-dir scanning beyond the fixed `workflows/*` depth.
