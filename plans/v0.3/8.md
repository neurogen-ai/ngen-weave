# Step 8 — filters, search, sorting

PRD reference: "Graph canvas" → "Filtering and sorting".

## Goals

- Filter chips for node types and edge kinds, text search over node names and prompt text, and sidebar-only sorting. Filters affect both the canvas (dim or hide) and the sidebar lists.

## Detailed steps

1. Sidebar: a left panel on the canvas route listing nodes grouped by type (workers / control / human). Clicking a sidebar entry triggers the same focus-and-open behavior as clicking the node.
2. Filter state (`apps/web/src/lib/filters.svelte.ts`): a single store holding
   ```ts
   { nodeTypes: Set<'worker'|'control'|'human'>,   // empty = all shown
     edgeKinds: Set<EdgeKind>,                      // 'edge'|'pass'|'fail'|'route'|'observer'
     search: string }
   ```
   One derived selector computes, per node and per edge, `visible | dimmed`. This one function is the whole filtering brain; both canvas and sidebar consume it.
3. **Edge-kind semantics** (the PRD's key subtlety): an edge's kind is partly determined by its *target node type*. "Observer" kind covers edges into observer-reroute targets — this is what makes "hide all observer wiring" possible. Implement kinds as:
   - control pass branch, control fail branch, human route, observer reroute: by origin as mapped in step 7
   - plain edge: everything else
   Filtering to hide observer wiring = deselecting the "observer reroute" chip. Verify with a fixture that a heavily-connected control node plus observers becomes readable after that single deselect.
4. Search matches node name substring (case-insensitive) and prompt body text. Prompt bodies come from `WorkflowDetail.files` (decode the node definition file, strip frontmatter). Non-matching nodes dim; matching count shown next to the search box.
5. Sorting applies to **sidebar lists only**: by name, by type, by topological order (topological order from the layout graph; cycles break ties by declaration order). A small select in the sidebar header. Canvas never re-sorts — position encodes topology.
6. Dim-vs-hide rule: filtered-out elements dim on the canvas by default; hold-to-peek is unnecessary. Sidebar hides non-matching entries entirely.

## Tests

- Selector tests: each chip toggles exactly its class of elements; combined filters intersect correctly.
- Observer-wiring fixture test: deselecting the observer chip dims every observer-originated edge and nothing else.
- Search: matches name, matches prompt text, no match → all dimmed + zero count; case-insensitivity.
- Sort modes produce the three documented orders; topological order respects edges of a cyclic fixture.
- Canvas receives unchanged positions when sorting changes (sort never touches layout).

## Out of scope (tempting, do not build)

- Saved filter presets, URL-encoded filter state beyond what falls out free from step 9's deep-linking work.
- Regex or fuzzy search. Substring is specified; fancier matching is scope creep with test burden.
- Hiding nodes on the canvas (dim only) — PRD says dim/hide, pick dim uniformly and document it in code.
- Per-filter-type counts beyond the search match count.
- Filtering workflow-level elements (contracts panel) — filters are about the graph.
