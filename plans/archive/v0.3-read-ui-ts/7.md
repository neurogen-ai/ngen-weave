# Step 7 — graph canvas

PRD reference: "Scope" item 2, "Graph canvas".

## Goals

- Route `/<name>`: the workflow rendered in Svelte Flow as an auto-laid-out left-to-right graph with typed edges, pan/zoom, fit-to-view, minimap, click-to-focus, and hover highlighting.

## Detailed steps

1. Fetch `WorkflowDetail` for the route param. Invalid workflow → render the errors dialog from step 6's component and no canvas.
2. Node/edge mapping (`apps/web/src/lib/graph.ts`, pure functions, heavily tested):
   - One Svelte Flow node per workflow node: id = node name; data carries type (worker/control/human), model+variant, observer count, description.
   - Node visual differentiation by type: distinct badge/color per worker/control/human using theme tokens. Keep shapes uniform (rounded rect); color and badge carry the meaning.
   - Edges:
     - plain edge `from → to` → default edge
     - control `pass:` target → edge labeled "pass", success-styled
     - control `fail:` target → edge labeled "fail", danger-styled
     - human node `routes[]` → one edge per route, labeled with the route's `when` expression (or "default")
     - observer reroute targets → edges labeled with the observer action, dashed styling
   - Cycles fall out naturally as back-edges once laid out; no special casing.
3. Auto-layout with dagre (or elkjs if dagre proves insufficient for back-edges): direction LR, rank separation generous enough that a 15-node graph fits at typical laptop size after fit-view. Run layout once per graph load, before handing positions to Svelte Flow.
4. Canvas chrome: fit-to-view button, minimap (bottom-right), zoom controls, background grid. On mount, call fit-view so the whole graph is legible immediately.
5. Click-to-focus: clicking a node animates the camera to center it and opens the detail panel (the panel itself is step 9; this step opens a stub panel showing just the node name). Clicking empty space closes it.
6. Hover highlighting: on node hover, connected edges and neighbor nodes go accent-colored; everything else dims (opacity via CSS transition). Pure CSS class toggling driven by two Svelte Flow event handlers; no re-layout.
7. Detail polling: reuse step 6's polling pattern on this route against `getWorkflow(name)`; on hash change refetch detail and re-layout. Unchanged hash → zero work.

## Tests

- `graph.ts` mapping tests over a fixture covering every edge kind: counts and labels correct; control nodes produce exactly pass/fail edges; human routes produce one edge per route plus default; observer reroutes present.
- Layout test: dagre output positions all nodes without overlap (bounding-box check) for a 15-node fixture; all edges point left-to-right except genuine cycle back-edges.
- Component test: renders N nodes for fixture; hover adds highlight class to neighbors and dim class elsewhere.
- Hash-gating test: unchanged hash triggers no remount of the canvas.

## Out of scope (tempting, do not build)

- Dragging nodes / persisting positions. Layout is computed each load; position persistence is editor territory.
- Edge routing customization, bezier vs smoothstep debates beyond picking one and moving on.
- Minimap node-type coloring, export-to-image, selection rectangles, multi-select.
- Zoom-dependent level-of-detail rendering (hiding labels when zoomed out).
- Parallel-execution or subworkflow visuals (non-goals).
