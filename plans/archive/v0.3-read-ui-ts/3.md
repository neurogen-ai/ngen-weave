# Step 3 — `packages/web-api` scaffold + list endpoint

PRD reference: "Read API contract", "Serving".

## Goals

- New package `packages/web-api`: an HTTP server exposing workflows read-only as JSON. This step delivers the scaffold and `GET /api/workflows`.
- Shared response types live in core (`packages/core/src/api-types.ts`) so the web app imports the same definitions.

## Detailed steps

1. Scaffold: `packages/web-api` with Hono (small, runs on Node without a framework lock-in; swap for whatever the repo prefers if it already standardized otherwise — the plan is framework-agnostic below). Entry: `src/server.ts` exporting `createApp(): { fetch }`. No top-level listening in library code; the CLI (step 10) binds the port.
2. `packages/core/src/api-types.ts`:
   ```ts
   export interface WorkflowListItem {
     name: string;
     description: string | null;   // graph-level description
     hash: string;
     valid: boolean;
     errors: string[];
   }
   ```
3. Route `GET /api/workflows` → `WorkflowListItem[]`, built by calling step 2's `discoverWorkflows(projectRoot)` per request, plus one graph parse for valid entries to extract the graph-level `description`. Invalid entries report `description: null`.
4. Project root resolution: constructor parameter with default = cwd. The server takes `{ projectRoot }`; nothing else configurable.
5. Health route `GET /api/health` → `{ ok: true }`.
6. Read-only enforcement, mechanically checked: a vitest test asserts no route in the app responds to POST/PUT/PATCH/DELETE with anything but 405. Write this as a loop over all registered routes.

## Tests

- List returns fixture workflows with correct names, validity, errors, hashes.
- Invalid workflow appears with `valid: false` and its error list; does not crash siblings.
- 405 test above passes for every route.
- Response JSON matches `WorkflowListItem[]` (parse-and-validate against the type's runtime shape).

## Out of scope (tempting, do not build)

- Detail endpoint (step 4). Resist adding it early even though discovery already parses graphs.
- CORS headers. Same-origin serving via `loom ui` makes them unnecessary; add only when deployment exists.
- Compression, rate limiting, logging middleware beyond a minimal request log behind a debug flag.
- OpenAPI/Swagger generation. The contract is three endpoints and typed in core.
- ETag/If-None-Match handling. The client compares hashes itself; HTTP caching is redundant machinery here.
