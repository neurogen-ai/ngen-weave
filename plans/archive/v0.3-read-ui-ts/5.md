# Step 5 — `apps/web` scaffold

PRD reference: "Stack", "Light and dark themes from day one".

## Goals

- SvelteKit SPA-mode app with Tailwind, shadcn-svelte, and light/dark theming via CSS variables, wired to the API through a typed client. By the end of this step the app loads and displays a placeholder page fetching `/api/workflows` in dev.

## Detailed steps

1. `apps/web`: SvelteKit + TypeScript, `@sveltejs/adapter-static` with SPA fallback (`fallback: 'index.html'`, all routes prerender = false). Add to root workspaces.
2. Tailwind CSS v4 (or the repo's preferred major) with design tokens as CSS variables in `apps/web/src/app.css`:
   - Tokens: background, foreground, muted, border, card, primary, accent, success, warning, danger — following shadcn-svelte's variable naming so its components consume them directly.
   - Two sets: `:root` (light) and `.dark`. Dark class toggled on `<html>`; default follows `prefers-color-scheme`, manual toggle persisted to localStorage.
3. shadcn-svelte init; add only the primitives needed later: button, card, badge, dialog/sheet, tabs, tooltip, input, select. Do not pre-add more.
4. Dev proxy: vite dev server proxies `/api/*` to the web-api dev port so no CORS exists anywhere.
5. Typed API client `apps/web/src/lib/api.ts`:
   ```ts
   import type { WorkflowListItem, WorkflowDetail, SchemaResponse } from '@agent-loom/core';
   export async function listWorkflows(): Promise<WorkflowListItem[]> { ... }
   export async function getWorkflow(name): Promise<WorkflowDetail | InvalidDetail> { ... }
   export async function getSchema(name, file): Promise<SchemaResponse> { ... }
   ```
   Types imported from core. No second definition of any response shape.
6. Placeholder route `/` rendering the list endpoint's JSON count ("3 workflows") to prove the wiring end to end. Replaced in step 6.

## Tests

- Build succeeds in SPA mode; `vite preview` serves index fallback on deep links.
- Token test: both themes define the identical set of variable names (a vitest test parses app.css and compares key sets) — prevents drift when someone adds a token to one theme only.
- API client unit tests against a mocked fetch (shape passthrough, error on non-2xx).

## Out of scope (tempting, do not build)

- Any real view beyond the placeholder. List view is step 6.
- SSR/hybrid rendering. SPA mode is decided; do not "fix" the SEO or first-paint tradeoff.
- Theme animation, multiple accent palettes, font loading pipeline. System font stack is fine for v0.3.
- A router-level layout system, breadcrumbs, or nav chrome beyond what steps 6–9 need.
- Component library beyond the listed primitives ("we'll probably need table/chart" is not a reason).
