# Step 9 — detail views

PRD reference: "Detail views", "Plain-language" and "Author" presentation modes, workflow-level contracts.

## Goals

- Node detail panel (opens from canvas/sidebar click): metadata plus two tabs — plain-language (default) and author. Workflow-level contracts view in both modes.

## Detailed steps

1. Plain-language generator (`apps/web/src/lib/plain.ts`, pure functions over `ParsedGraph` node + graph context):
   - Template per node type, assembled from structure only:
     - worker: "Calls model `<model>` (variant `<variant>`) to <description or 'process input'>. Passes output to <children>."
     - control: "Checks <description or 'a condition'>; routes to <pass target> on pass, <fail target> on fail."
     - human: "Pauses for a person to review. Routes to <targets> based on the decision."
   - Observers appended: "<n> observer(s) watch this node: pause on <cond>, reroute to <target> on <cond>." Render each observer's `when` expression verbatim — expressions are already readable.
   - Fan-in noted when present: "Combines inputs from <parents>: <field> ← <parent>."
   - Deterministic: same graph → same string. No LLM anywhere.
2. Node panel component, tabs via shadcn tabs:
   - **Plain-language tab (default)**: generator output as short prose lines, then the node's `description` field quoted beneath it if present.
   - **Author tab**: 
     - prompt body with rendered/verbatim toggle (rendered = markdown render of the body; verbatim = pre block with exact file bytes from `files`)
     - input/output schemas as structured property tables: property name, type, required flag, description from schema. Expandable rows. A "view JSON" toggle shows verbatim JSON behind a further click.
     - full frontmatter fields listed flatly (model, variant, temperature, observers with their params).
3. Workflow contracts view: a collapsible section above/beside the canvas showing workflow-level input/output schemas (same table treatment), run configuration (`max_steps`, retries), artifacts list, and the graph-level description. Both plain-language and author modes: plain-language renders the contract schemas through the same property-table + one-line summary; author mode adds verbatim toggles. Reuse the components from step 2 — do not fork table rendering.
4. Deep links: clicking a node updates the URL to `/<name>?node=<node>`; loading that URL opens the canvas focused on that node with its panel open. Back button walks node selection history.

## Tests

- Generator tests: golden strings for one fixture per node type, an observered worker, a fan-in node, and a human with routes. Determinism asserted by calling twice.
- Schema table test: required properties flagged; nested `$ref` resolution shown via the API's resolved schema (the client never resolves refs itself).
- Tab behavior: plain-language is default on open; toggle state does not reset on node change within the session.
- Deep-link test: mount route with `?node=quality_gate` → panel open for that node.
- Markdown rendering escapes HTML by default (prompt bodies are untrusted-ish text).

## Out of scope (tempting, do not build)

- Any LLM-generated summary, even behind a feature flag. The PRD reserves the tab for it later; nothing ships now.
- Editing anything. Not even disabled buttons implying editability.
- Prompt template preview showing resolved `{{ input.* }}` values — there are no run inputs in v0.3; previews would be fake.
- Artifact content preview/templating (non-goal). Artifacts appear as config entries only.
- Copy-to-clipboard buttons beyond at most "copy prompt" if free during review.
- Print/export stylesheets.
