# Step 4 — smoke-runner model layer

PRD reference: "Inference" section; "The TypeScript engine after demotion".

## Goals

- Replace the pi/AI-SDK model layer in the smoke runner with a `CompletionProvider` adapter that reads models.json and calls OpenAI-compatible HTTP endpoints. Structured output validated against the boundary schema regardless of provider support.

## Detailed steps

1. Remove pi and Vercel AI SDK dependencies from `packages/core`. The old model adapter code is deleted, not deprecated.
2. Keep the seam interfaces verbatim:
   ```ts
   interface CompletionProvider { complete(req): Promise<{ output: object; usage: Usage }> }
   interface NodeExecutor { run(input: object, ctx: NodeContext): Promise<NodeResult> }
   ```
3. Implement `HttpCompletionProvider` in `packages/core/src/models/http-provider.ts`:
   - Constructor takes the resolved models registry (from step 3) and a base-URL/env map.
   - Provider mapping for v0.2: `openrouter`, `openai`, `anthropic`, and any LiteLLM proxy (provider `litellm`, base URL from env). Each maps to an OpenAI-compatible `/chat/completions` request; anthropic uses its messages API shape. Auth via standard env vars (`OPENROUTER_API_KEY`, etc.) — read a small table, no credential store.
   - Request body includes reasoning effort from the resolved variant where the provider supports it (OpenRouter: `reasoning: { effort }`; otherwise omit silently).
   - Structured output: attempt provider-native JSON schema (`response_format`) when supported; validate the response against the node's output schema with ajv either way; invalid → `DataError` as v0.1 semantics dictate.
   - Map HTTP/timeout errors to `InfraError` so graph-level retries still apply.
4. Node-level resolution helper: `resolveModelCall(nodeDef, registry)` returns `{ id, baseURL, headers, reasoningEffort }`. Pure function, unit-testable.
5. Wire the existing smoke runner to use `HttpCompletionProvider` through the same factory the tests use, so tests can inject fakes.
6. Update example workflow's `models.yaml` → delete it; document in the example README that models.json at project root is now the single registry.

## Success criteria

- Smoke runner executes a worker node against a stub HTTP server (no real network) and produces validated output plus usage metadata for observers.
- No pi or AI SDK packages remain in any package.json or lockfile.

## Tests

- Unit tests over a local http server fixture (node:http): happy path, 429/500 → InfraError, malformed JSON → DataError, variant → reasoning-effort field present/absent per provider.
- Resolution helper: defaultVariant fallback, explicit override, unknown key error.

## Commits

- `feat(core): drop pi model layer for OpenAI-compatible CompletionProvider driven by models.json`

## Out of scope

- Streaming responses, token counting beyond what the response reports
- Provider plugins/adapters beyond the four listed mappings
- Retries inside the provider (graph retry policy owns that)
- Any Python-side inference code (the exporter emits LangGraph nodes using `init_chat_model`; that is steps 5–6)
