# agent-loom v0.2 PRD

Status: draft
Prerequisite: plans/v0.1/PRD.md (node model, schemas, graph semantics). This document revises the runtime story; it does not change the node vocabulary.

## What changed since v0.1

v0.1 specified a thin TypeScript engine as the executor. v0.2 replaces that decision: compiled LangGraph is the canonical execution backend. The TypeScript side keeps the loader, validator, and a smoke-test runner. Pi is no longer an inference dependency; it appears only as one consumer of loom's MCP server.

The motivation is interface economics. LangGraph provides durable execution, checkpointing, interrupts, a serving API, and Studio inspection that loom would otherwise rebuild. LiteLLM covers more providers than pi's catalog. And MCP decouples "agents can call workflows" from any particular agent vendor.

## Execution

One backend, canonical:

```
workflows/*.yaml ──(loom export)──▶ Python LangGraph ──▶ langgraph-server
```

`loom export <workflow-dir>` compiles a validated graph into a Python LangGraph project under `langgraph/`. Output is a build artifact, generated by CI, never hand-edited. Serving uses self-hosted langgraph-server; deployment docs are included but the server itself is not our deliverable.

Compilation map:

| loom construct | LangGraph construct |
|---|---|
| worker node | node function |
| control node boolean | conditional edge |
| fan-in input maps | state assembly at node entry |
| human node | `interrupt()` |
| observer actions | wrapper function around each node body |
| artifacts block | post-node sink |

Observer wrappers return `Command({ goto })` for reroute, raise `interrupt()` for pause, and return `END` for stop. All three observer actions therefore export with full parity. There is no documented-subset mode. If implementation surfaces something genuinely unmappable, the finding comes back here with evidence before anything is cut.

Checkpointer: SQLite by default, memory for tests.

### The TypeScript engine after demotion

`packages/core` retains:

- Full static validation (`loom validate`): schema resolution, name uniqueness, edge integrity, fan-in completeness, expression compilation, control `pass` booleans, workflow-level contract agreement.
- A smoke-test runner: executes small workflows in-process without Python, for test suites and quick iteration. Documented as non-authoritative. No dual-backend parity guarantee; if behavior ever diverges from LangGraph, LangGraph wins.

## Inference

Pi's model layer is dropped. Model calls go through LiteLLM via LangChain's `init_chat_model`, resolved from a loom-owned `models.json` at the project root (one file shared across all workflows in the repo):

```json
{
  "kimi-k3": {
    "provider": "openrouter",
    "id": "moonshotai/kimi-k3",
    "defaultVariant": "high",
    "variants": { "high": "high", "fast": "low" }
  }
}
```

Keys are the short names used inside workflow YAML. Variants map to reasoning-effort levels. Node-level `variant:` overrides `defaultVariant`. Auth uses provider environment variables and LiteLLM conventions; no loom-managed credential store.

Structured output uses the provider's native schema support where available and validates against the boundary schema regardless. The seam interfaces from the earlier draft stand unchanged:

```ts
interface CompletionProvider {
  complete(req): Promise<{ output: object; usage: Usage }>;
}
interface NodeExecutor {
  run(input: object, ctx: NodeContext): Promise<NodeResult>;
}
```

Adapters translate; they never extend.

## Workflow-as-tool: the MCP server

Loom ships an MCP server exposing workflows as tools. Any MCP client can call them; pi is the first documented consumer, not a special case.

- Manifest: project-root `loom.json` listing workflow directories.
- Registration: one tool per workflow. Tool name is the workflow `name:`; tool description comes from a new required `description:` field on graph.yaml, because agents choose tools by description. Parameter schema is the workflow's top-level input JSON Schema converted to the MCP tool-input format; the result content is the validated output object.
- Static validation runs at server startup. A broken workflow fails loudly there, not mid-conversation.
- Transport: stdio for local clients, HTTP for remote.
- Execution: synchronous and blocking. Calls dispatch to the canonical backend (a configured langgraph-server endpoint; local default starts one). Runs checkpoint to `.loom/runs/` as usual. Callers see inputs and final output only, never intermediate node traffic. The run's `max_steps` budget bounds call duration.

## Human review over the network

Remote execution makes the file artifact unreachable, so the review artifact gains a canonical JSON form: same fields as the YAML artifact, submitted through langgraph-server's interrupt/resume endpoints. File-based review (`.loom/runs/<id>/reviews/<node>.yaml`, completed as `.reviewed.yaml`) remains the local path, and both forms carry identical payloads so any future UI submits either without translation.

## Artifacts

Document creation is write-behind on outputs, not a node type. Graph-level block:

```yaml
artifacts:
  - from: finalize
    schema: schemas/report.json     # optional subset validation
    path: "out/{{ run_id }}/report.md"
```

The engine writes the referenced node's validated output whenever it completes. Plain JSON dumps in v0.2; templating deferred.

## Events

Run events are versioned JSONL at `.loom/runs/<id>/events.jsonl`. Node transitions, observer firings, retries, interrupts, and backend events merge into this one stream. Schema versioned in the first line of each file.

## Repo layout

TypeScript workspace monorepo:

```
packages/core             # loader, Zod schemas, validator, smoke runner
packages/cli              # loom validate | export | run | resume | status
packages/mcp              # MCP server
packages/export-langgraph # compiler to Python
langgraph/                # generated Python, committed, CI-built
```

Users never need the TS toolchain to serve workflows.

## Non-goals for v0.2

- Parallel execution within a workflow.
- Subworkflow nesting (invariant already enforced by the workflow-contract check).
- Loom-owned REST API beyond what langgraph-server provides.
- Templating in artifacts.
- Any pi-specific code paths. See v1.0 for the distribution roadmap.
