# Step 8 — events stream

PRD reference: "Events" section.

## Goals

- One versioned JSONL stream per run at `.loom/runs/<run-id>/events.jsonl` merging node transitions, observer firings, retries, interrupts, and backend events.

## Detailed steps

1. TS side (`packages/core/src/events.ts`): `EventWriter` — append-only JSONL writer with monotonically increasing `seq`, first line carrying the schema version via the envelope's `v` field (per PRD: schema versioned in the first line of each file; the envelope `v: 1` on every line makes that trivially true). Atomic appends: single `fs.appendFile` per event.
2. `EventReader`: read + validate a whole file against the step 2 envelope schemas; used by tests and `loom status`.
3. Python side: generated `_runtime.py` gets an emitter writing to the same path format. Every node entry/exit, observer firing, retry attempt, and interrupt emits through it. Backend-level events (langgraph's own stream) are bridged where the server exposes them; anything not mappable to a typed payload goes out as `type: 'backend'` with the raw payload under `payload`. Do not invent typed variants for backend internals.
4. Run directory creation: `.loom/runs/<id>/` created by whoever starts a run (TS CLI in step 9, smoke runner now). The smoke runner also writes events.jsonl using `EventWriter` so both backends produce identical shapes.
5. Correlation: `runId` and `seq` come from the run, not the process. Python reads the run dir from env `LOOM_RUN_DIR` injected at dispatch time.

## Success criteria

- A pytest run of the exported example produces an events.jsonl validating against the envelope schemas, containing node_start/node_end for every executed node and an interrupt event for the human node.

## Tests

- Unit: EventWriter seq monotonicity across writer restarts (append mode), reader validation errors on corrupted lines.
- Pytest: example run's events file validates via a small Python-side check or by copying the file into a vitest fixture test. Prefer the vitest fixture approach so validation logic lives once, in TS.

## Commits
- `feat(core): versioned JSONL event writer/reader`
- `feat(export): emit runtime events from generated LangGraph nodes`

## Out of scope
- Streaming events to clients (MCP callers see final output only, per PRD)
- Event querying/filtering tooling beyond `loom status`
- Rotation, compaction, retention policies
- Websockets or push of any kind
