# Step 2 — schema revisions

PRD reference: "Inference" (models.json), "Workflow-as-tool" (description field), "Artifacts", "Events".

## Goals

- Extend the Zod schemas in `packages/core/src/schema` for every new or changed structure. No behavior changes yet; loader/validator wiring is step 3.

## Detailed steps

1. **Graph config**: add required top-level `description: string` (non-empty after trim). Add optional `artifacts:` array where each entry has:
   - `from: string` — must name a node (validated in step 3)
   - `schema?: string` — path to a JSON Schema file, resolved relative to graph.yaml
   - `path: string` — output path template containing `{{ run_id }}`; validate the literal contains that placeholder and no other placeholders
2. **Model registry**: replace `models.yaml` with `models.json`. New Zod schema:
   ```ts
   modelsJson = z.record(z.string(), z.object({
     provider: z.string(),
     id: z.string(),
     defaultVariant: z.string().optional(),
     variants: z.record(z.string(), z.union([z.string(), z.object({ reasoningEffort: z.enum(['low','medium','high']) }))])
   }))
   ```
   Variant values normalize to `{ reasoningEffort }`: a bare string `"high"` becomes `{ reasoningEffort: 'high' }`. The file lives at the project root (the directory containing `workflows/`, or wherever `loom.json` says — see step 10 for the manifest; for now resolve as `<cwd>/models.json` with an explicit override option on load).
3. **Node frontmatter**: worker/control model nodes keep `model:` (short key into models.json) and optional `variant:`. Remove any pi-era fields if present.
4. **Event envelope** (`packages/core/src/schema/events.ts`):
   ```ts
   eventEnvelope = z.object({
     v: z.literal(1),
     ts: z.string(),            // ISO 8601
     runId: z.string(),
     seq: z.number().int().nonneg(),
     type: z.enum(['node_start','node_end','observer_fired','retry','interrupt','resume','backend','run_end']),
     node: z.string().optional(),
     payload: z.unknown()
   })
   ```
   Each event type's payload gets its own Zod schema in the same file (e.g. `observerFiredPayload = { observer, action, metadata }`). Keep it flat and small.
5. **Review artifact JSON form**: add `reviewArtifact = z.object({ node, input, fields, decision })` mirroring exactly the YAML artifact's fields. This type is shared by both forms; write a comment saying so.
6. Export a JSON-Schema serializer helper (`zod-to-json-schema` dep) for the boundary schemas used by generated Python (step 5 consumes this).

## Success criteria

- All new schemas compile and round-trip: parse sample YAML/JSON fixtures for each new structure.

## Tests

- Schema unit tests: valid graph.yaml with description + artifacts parses; missing description rejected; artifacts path without `{{ run_id }}` rejected; models.json fixture parses with string and object variant forms; event envelope rejects unknown types and non-integer seq.
- Old fixtures without `description` are moved to a "legacy" test folder asserting rejection (they are now invalid by definition).

- Writing or reading actual events.jsonl files (step 8)
