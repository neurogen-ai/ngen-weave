# Step 3 — loader + validator updates

PRD reference: "Inference" (models.json at project root), "Workflow-as-tool" (startup validation), "Artifacts".

## Goals

- `loom validate` enforces the new schema rules. Loading resolves models.json once per project.

## Detailed steps

1. Loader: after parsing graph.yaml, require `description` (Zod already rejects; make the error message say "graph.yaml requires a description: agents choose tools by it").
2. Validator additions:
   - Each `artifacts[].from` names an existing node in the graph.
   - Each `artifacts[].schema`, if present, resolves and parses as JSON Schema; additionally check the referenced node's output schema *validates against* it as a subset (use the same ajv instance v0.1 uses for boundary validation: compile the artifact schema and assert the node's output schema's compiled sample instances pass — simplest correct approach: compile both, validate a set of generated samples from the node output schema via json-schema-faker, or if that is flaky, do a structural subset check on required properties only; pick one approach and document it in code).
   - Every node-level `model:` key exists in the loaded models.json. This makes model resolution a static check.
   - Every `variant:` on a node exists in its model's `variants` map.
3. Models loading (`packages/core/src/models.ts`): `loadModels(projectRoot, overridePath?)` reads `<projectRoot>/models.json` (or the override), parses with the step 2 schema, returns a resolved registry. One load per process; pass it into validation and the smoke runner rather than re-reading.
4. Project root discovery: walk up from the workflow dir to the nearest directory containing `models.json`; error if none found. Keep it under 20 lines; no config file yet.
5. Update `loom validate` output to include new checks in its existing error list format.

## Success criteria

- Example workflow updated with `description` and one artifact entry validates clean.
- Workflows missing description, referencing unknown models/variants, or wiring artifacts to nonexistent nodes fail validation with precise messages.

## Tests

- Validator unit tests for each new rule (one test per rule, plus one happy-path).
- models.json not found → ConfigError naming the searched path.
- Variant normalization: `variant: fast` resolves through `defaultVariant` when node omits variant.

## Commits

- `feat(core): enforce description, artifacts, and model-registry checks in validator`
- `feat(core): project-root models.json loader`

## Out of scope

- `loom.json` manifest (step 10)
- Making any model calls or touching provider SDKs (step 4)
- Engine changes; artifacts are only validated here, written by the backend/smoke runner later
- Recursive project-root search beyond walking up directories (no globbing, no multi-root workspaces)
