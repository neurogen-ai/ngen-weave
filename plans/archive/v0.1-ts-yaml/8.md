# Step 8 — control node executor

PRD reference: "Control nodes" section and the programmatic canonical example.

## Goals

- ControlExecutor with two modes: `programmatic` (pure logic over input, no model) and `model` (worker-style call whose output must include boolean `pass`).

## Detailed steps

1. Programmatic mode. The PRD's canonical example shows a body of `checks:` entries:

   ```yaml
   checks:
     - when: "input.word_count < min_words"
       pass: false
   min_words: 200
   ```

   Semantics: evaluate each check's `when` in order against bindings `{ input, ...params }`; the first matching check determines `pass`. If none match, `pass: true` (default-allow; document this). Output value is `{ pass, matched_check?: when-string }`, validated against the node's output schema (which requires boolean `pass`). Next = `{kind:"passfail"}`.
   - Parse the body as YAML (it's YAML under markdown). Compile all `when` expressions at load time in step 4's validator (extend step 4 to compile programmatic control checks too, allowed identifiers: `input.*` fields + params).
2. Model mode: identical to worker execution (step 7), except:
   - Output must parse to an object containing boolean `pass` (guaranteed by required-schema validation).
   - If output invalid → data failure semantics like workers: store raw, set `last_output_valid=false`. For routing, treat as `pass: false` so the fail edge runs (documented decision; observers can gate it).
   - Next = `{kind:"passfail", pass}`.
3. Wire both into the engine's executor map by `type` + `mode`.

## Success criteria

- Programmatic control node routes on its checks without any model call.
- Model control node fills `pass` via the adapter and routes accordingly.

## Tests

- PRD quality-gate example: input below min_words routes fail; above routes pass.
- No matching check defaults to pass.
- First-match-wins ordering.
- Model mode with fake adapter returning `{pass:true,...}` follows pass edge; invalid JSON follows fail edge with last_output_valid false.
- Programmatic node with a model field rejected at load (already covered in step 2 schemas; add a loader-level test).

## Commits

- `feat(nodes): programmatic and model control executors`

## Out of scope
- Multiple conditions per check (AND beyond expression syntax), else-chains, switch/match nodes
- Retry-on-fail loops (workflow authors build them with edges)
