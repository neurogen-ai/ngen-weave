# Step 7 — worker node executor

PRD reference: "Worker nodes" section, including prompt placement rules and no-retry rule.

## Goals

- WorkerExecutor: template the prompt with `input.<field>`, call the model adapter, validate output against the node's output schema, return it. Invalid output is data, not error.

## Detailed steps

1. `src/engine/template.ts` — minimal mustache-style substitution: `{{ input.brief }}` → stringified value from input. Supported: dotted paths only. Missing path throws `DataError`. No loops/conditionals/transforms. Whitespace-trimmed tags.
2. `src/engine/nodes/worker.ts` — `createWorkerExecutor(adapter: ModelAdapter): NodeExecutor`:
   - Resolve model via registry (alias + variant + temperature from frontmatter).
   - Prompt source: resolved in step 4 already (prompt key wins over body). Template it.
   - Call adapter; on success parse output text as JSON, validate against output schema with Ajv.
   - Valid JSON → `{ output, next: {kind:"edge"} }`. Invalid JSON or schema-invalid → this is a **data failure**: per PRD the worker always emits something. Represent invalid output as `{ outputValid: false, raw: text }` passed downstream? No — the engine contract needs a value for edges. Decision: return output = `{ pass: false, raw_output: <text> }` is wrong (that's control semantics). Instead: ExecResult gains `outputValid: boolean`; the engine stores raw text as the node's output when invalid, sets metadata `last_output_valid`, and continues along the normal edge. Gating is downstream's job. Document this in code.
   - Populate metadata fields from ModelResult plus timing (`elapsed_ms`) and iteration count supplied by RunContext.

## Success criteria

- A worker node with a fake adapter produces validated output and advances along its edge.
- Schema-invalid output flows onward with `last_output_valid: false`, run continues.

## Tests

- Prompt templating: simple field, nested path, missing path errors.
- Valid JSON output passes schema and lands in state.outputs.
- Output that is not JSON / fails schema: run does not fail, state records invalid flag.
- Adapter InfraError retried by engine policy (integration with step 5).

## Commits

- `feat(nodes): worker executor with prompt templating and boundary validation`

## Out of scope
- Any retry of invalid outputs; observers reacting to them (step 10)
- System prompts beyond an optional future field; multi-turn chat history
- Control/human executors (steps 8–9)
