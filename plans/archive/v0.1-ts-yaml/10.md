# Step 10 — observers

PRD reference: "Observers (meta-nodes)" section.

## Goals

- Preset refs and inline observer definitions resolve into a common shape; every host-node activation evaluates triggers over the six-field metadata and applies actions.

## Detailed steps

1. `src/engine/observers.ts` — `resolveObservers(node, workflowDir): ResolvedObserver[]`:
   - For `ref:` entries: load the preset `.md` frontmatter (`when`, params, `action`), then overlay keys from the referencing block (e.g. `max_tokens: 2048` overrides preset value). Relative ref paths resolve against the referencing file; `~/` expands.
   - Inline entries: build directly from the block.
   - Compile each `when` at load time; allowed identifiers: the six metadata fields + the observer's own param keys. Extend step 4's validator to do this for every node.
2. Evaluation hook in the engine (step 5's stepRun), after an executor returns and metadata is assembled:
   - Evaluate triggers in declaration order against `{ iterations, tokens_in_context, tokens_total, cost_usd, elapsed_ms, last_output_valid }` plus params.
   - First firing trigger wins. Apply its action:
     - `pause` → run status `paused`, persist, halt (resume continues the same node? No — pause happens after activation completed; resume proceeds to next node. Document that pausing is post-activation).
     - `stop` → run status `stopped`.
     - `reroute` → discard this activation's output (do not store it), mark node `skipped`, jump to target node. Step counter still increments.
   - Append every evaluation result (fired or not) to `observer_events` in state.json with the metadata snapshot.

## Success criteria

- PRD example works: worker referencing max-tokens-observer.md pauses when context exceeds 4096; inline cost observer reroutes on breach with override values applied.

## Tests

- Preset loading + key override (override beats preset).
- Trigger fires at boundary (> not >=) using crafted metadata.
- Reroute discards output, marks skipped, lands on target node.
- Pause/stop halt the run with correct statuses; resume from paused continues.
- Observer events logged including non-firing evaluations.
- Unknown identifier in observer when fails static validation.

## Commits

- `feat(observers): preset resolution with key overrides`
- `feat(engine): observer evaluation loop with pause, stop, reroute actions`

## Out of scope
- Standalone observer nodes; observers observing other observers
- SQL queries, aggregate/window functions across activations
- Any metadata field beyond the frozen six
