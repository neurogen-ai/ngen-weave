# Step 11 — CLI

PRD reference: "CLI" section.

## Goals

- Wire the four commands over the pieces from steps 4–10, replacing the placeholder from step 1. Use node's `util.parseArgs`; no commander/yargs dependency.

## Detailed steps

1. `src/cli/main.ts` dispatch table:
   - `loom validate <workflow-dir>` — call `validateWorkflow`; print each error on its own line with file context; exit 1 if any; print `<name> is valid` and exit 0 otherwise.
   - `loom run <workflow-dir> [-i input.json]` — load workflow; read input JSON from `-i` file or stdin; `startRun`; then loop `stepRun` until halt or done; print per-node transitions (name, status) to stdout; final line: run id + status.
   - `loom resume <run-id>` — locate `.loom/runs/<run-id>` under cwd's `.loom/runs` (allow `-r` root override); handle human-review pickup (step 9); continue stepping; same output style as run.
   - `loom status <run-id>` — pretty-print state.json: status, steps used vs budget, per-node statuses, last event.
2. Exit codes: 0 success/paused/waiting/stopped-with-artifact, 1 validation failure, 2 run failed. Document in README section.
3. Errors: ConfigError → stderr with message, exit 1. DataError/InfraError after retries → the run's error report path (already persisted by engine), print summary, exit 2.
4. README.md at repo root: what agent-loom is (two paragraphs from PRD problem statement), quickstart with the example workflow, CLI reference, artifact contract for humans. Keep it short.

## Success criteria

- All four commands work against the fixtures from step 4 and the example from step 12.

## Tests

- Integration test spawning the built CLI: validate good fixture exits 0; broken fixture exits 1 with the right message on stderr.
- Run a stub-executor workflow via CLI to done; status shows done; resume of a waiting_human run picks up a reviewed artifact.
