# ngen-weave v0.2.1 implementation plan

Status: ready to implement.

## Context

v0.2.0 shipped RunService serving (FastAPI + MCP), SQLite storage, budgets, observers, and AgentNode, all merged to main. The post-merge evaluation found one real defect (per-Engine drive state shared between concurrent drives) and several small robustness and consistency gaps. A follow-up concurrency audit of the engine then found that its scheduling fencing — relay nodes aligning fan-in depths, dispatch delivery through a last-wins state channel — is unsound under loop re-entry and fences basic structures (a control node retrying a worker until completion) behind compile errors. This patch is therefore a realignment release with two traceability sources: the v0.2.0 review findings (Branches A–C) and the realignment decision (Branch D), which strips the scheduling fencing so the engine is a pure LangGraph wrapper as far as graph scheduling goes — nodes fire when triggers arrive, superstep concurrency stays LangGraph's. Simple loop structures with retry become the supported shapes; join freshness, dispatch delivery, and scheduling policy are deferred to `plans/design/loops-and-joins.md`.

Files touched: `engine/runner.py`, `engine/store.py`, `config.py`, `workflow.py`, `wiring.py`, a new `local_service.py` in core, the local-service tests moved into core, `tests/conformance/test_run_service.py`, `tests/e2e/test_v02_criteria.py` (import line only), `docs/engine/execution.md`, five `pyproject.toml` files. `plans/design/loops-and-joins.md` is pre-authored with this amendment; Branch D references it, it is not an implementation deliverable.

Depends on: nothing new. Fixes trace to the v0.2.0 review findings; Branch D traces to the post-release concurrency audit. Governing docs if more detail is ever needed: `plans/releases/v0.2.md`, `plans/design/artifact-store.md`, `plans/design/constants.md`, `plans/design/loops-and-joins.md`.

## Goals

1. Two runs driven concurrently by one Engine cannot corrupt each other's outcomes.
2. Cancellation survives status races between peek and set.
3. One malformed legacy run file cannot prevent store or server startup.
4. `LocalRunService` stops depending on the server package, so stdio/MCP-only installs genuinely avoid FastAPI (closing the F1 gap flagged in review).
5. Pin `RunSummary.cost_usd` accuracy in the conformance suite and document exact `Budget.steps` counting semantics.
6. Realign engine execution to LangGraph-native scheduling: remove the relay depth-alignment machinery, restrict multi-parent fan-in to equal-depth acyclic joins, and support single-parent retry loops with defined semantics.

## Branch A — engine correctness (`fix/v021-engine`)

### Step 1: isolate per-drive outcome state

`Engine._drive` currently resets three instance attributes at the start of every drive and reads them again in `_resolve_outcome`: `self._waiting`, `self._boundary_stop`, `self._breach_emitted` (declared near `__init__`'s `_cancel_flags`; reset at the top of `_drive`). When two drives overlap behind `LocalRunService`, drive B's reset erases drive A's pause/cancel decision. Fix this by making the triple a value owned by one drive.

Contract. In `packages/ngen-weave-core/src/ngen_weave/engine/runner.py`:

One implementation trap to settle up front: the interrupt path inside the compile-time `_node_fn` closure writes `self._waiting = dict(interruption)` directly (the returned-to-review branch), which cannot reach a per-drive `_DriveState` object via `self`. The per-drive state must ride in `RunnableConfig` (`config["configurable"]["ngen_drive_state"]`, set by `_invocation_config`) or the waiting signal must travel through the emitter closure only (the emitter is created per activation from `config`, so it has access to whatever rides there). Pick one mechanism in this step and make the isolation test cover the waiting path explicitly, not just pause/cancel.

```python
@dataclass
class _DriveState:
    """Outcome bookkeeping for exactly one drive of one run."""

    waiting: dict | None = None  # set by the emitter on waiting_human
    boundary_stop: dict | None = None  # outcome of the last boundary breach
    breach_emitted: set[str] = field(default_factory=set)  # runs whose budget record landed
```

Thread one `_DriveState()` instance created at the top of `_drive` through every method that reads or wrote the old attributes:

- `_drive` and `_resolve_outcome(compiled, final)` become `_resolve_outcome(state, compiled, final)`.
- `_at_boundary(run_file, node_path, metadata)` becomes `_at_boundary(state, run_file, node_path, metadata)`.
- `_observe_boundary` takes `state` the same way (its pause path writes `boundary_stop`).
- The record emitter factory `_emitter(run_id, node_path)` becomes `_emitter(state, run_id, node_path)`; its closures write `state.waiting`.
- Every other write/read site found by `grep -n "_waiting\\|_boundary_stop\\|_breach_emitted" runner.py` moves to the passed-in state.

Delete the three attributes from `__init__`. `self._cancel_flags` stays an Engine-level `set[str]` deliberately: cancel requests must be visible to whichever drive is running that run id. Add one comment beside it saying so.

Reads of `self._latest_waiting(run_file)` and the resumed-seed path are unrelated; leave them alone.

Regression test. New file `packages/ngen-weave-core/src/ngen_weave/engine/test_drive_isolation.py`, following the fakes style of `test_budget.py`:

```python
async def test_concurrent_drives_keep_outcomes_separate() -> None:
```

One Engine, two workflow instances whose configs differ in budget: run A gets `Budget(steps=1)` (must pause at its first boundary carrying a `budget_exhausted` record), run B has no budget (must complete). Launch both with `asyncio.gather(engine.run(...), engine.run(...))` using different run ids. Assert: A's result status `"paused"` with non-None waiting info, exactly one `budget_exhausted` among A's records and none among B's; B's result status `"completed"` with a validated output. Then rerun the whole test body twice inside one session via a loop to catch ordering flakiness. If the fake provider in `fakes.py` cannot express two workflows with distinct budgets on one engine, extend the fake; do not weaken the assertion.

Out of scope: changing when boundaries fire; touching `run.cel`/observer semantics; renaming any public method; converting the driver loop to async pools beyond `gather`.

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine -q` (isolation test green, all prior engine tests green); `uv run pytest -q` overall; `uv run ruff check .`.

### Step 2: race-safe cancellation

`Engine.cancel` decides from a `peek` whether to add a cancel flag or immediately `set_status("cancelled")`. Between peek and set, another actor can finish or resume the run, so a stale immediate-set can land on an unexpected state. Make the status transition conditional in SQL.

Contract. In `packages/ngen-weave-core/src/ngen_weave/engine/store.py`, extend the existing method:

```python
def set_status(
    self, run_id: str, status: RunStatus, expected: frozenset[RunStatus] | None = None
) -> bool:
    """Persist one status column update.

    With expected, the update applies only when the current status is a
    member; returns whether a row changed. Unknown run ids raise
    UnknownRunError either way.
    """
```

Single `UPDATE runs SET status = ? WHERE run_id = ?` plus, when `expected` is given, `AND status IN (...)`; `rowcount == 1` is the return. Import `UnknownRunError` from `ngen_weave.service` (it exists there today).

In `runner.py`, `Engine.cancel` becomes exactly:

```python
def cancel(self, run_id: str) -> None:
    run_file = self.store.peek(run_id)
    if run_file is None:
        raise UnknownRunError(run_id)
    if run_file.status in {"completed", "failed", "cancelled"}:
        return  # already terminal; cancelling again is a no-op
    if run_file.status == "running":
        self._cancel_flags.add(run_id)
        return
    self.store.set_status(run_id, "cancelled", expected=frozenset({"paused", "waiting_human"}))
```

A False return here means the run reached a terminal status in the race window, which is equivalent to the no-op case; do not retry or warn. Also sweep stale flags: in `_drive`, the existing `_cancel_flags.discard(run_id)` runs on the `"cancelled"` branch only; move one unconditional `discard` call so every terminal outcome (completed, failed, cancelled, waiting_human) clears the flag for its run id, and delete the now-redundant discard inside the cancelled branch.

Tests. Extend `packages/ngen-weave-core/src/ngen_weave/engine/test_budget.py` (cancel behaviour lives there today) alongside the existing double-cancel and cancel-between-transitions cases:

- `test_cancel_racing_completion_is_noop`: pause run, drive it to completion out-of-band (resume with raised cap via a second task), call `cancel` after completion; expect no exception, status stays `"completed"`, no `cancelled` record appended.
- `test_set_status_expected_mismatch_returns_false`: direct store-level check of the new contract, including the UnknownRunError path.

Out of scope: cross-process cancellation (the docstring already scopes cancel to same-process); changing who may cancel; any HTTP route changes.

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine -q`; then `uv run pytest packages/ngen-weave-server/tests/conformance packages/ngen-weave-mcp/tests -q` since conformance exercises cancel through every backend.

## Branch D — execution realignment (`refactor/v021-langgraph-native`)

Realigns engine execution to LangGraph's native scheduling semantics (fire on trigger, superstep concurrency stays LangGraph's): the engine stops fencing scheduling. Unblocks basic loop structures — a control node retrying a worker until completion, an observer/budget boundary landing mid-loop — and removes the relay depth-alignment machinery, which is unsound under partial loop re-entry (stale co-parent channels feed joins silently on iteration 2+; relays converted loud first-iteration failures into silent ones). Rebases on A: both branches edit `runner.py`, but in disjoint hunks (A: `_drive`/`_emitter`/`_resolve_outcome`; D: relay code, docstrings, one comment). D lands after A.

The execution-model docs work discussed during plan review (sequentiality-honesty docstrings, record-ordering guarantee, known-limitations list) is absorbed here: D owns all execution-model docs so they land in the same commit as the mechanism change.

### Step 6: drop relay depth alignment; compile-check join depth

`packages/ngen-weave-core/src/ngen_weave/engine/runner.py`:

- `_wire_static_edges` loses relay insertion entirely: no `_levels`/`_back_edges` calls, no `relay_seq`; each static edge is a plain `builder.add_edge(src, dst)` (or `add_edge(src, END)`).
- Delete `_levels` and `_back_edges` from `runner.py`; the algorithms move to `workflow.py` (below). Relay insertion is deleted outright — the equal-depth validation removes the need for it.
- `_consume_root`'s comment "relay steps write nothing" is updated: with relays gone, every streamed update key is a wiring node or `__interrupt__`; keep the disjointness guard (it is what skips interrupt chunks) and fix the comment.
- Module docstring drops "sequential workflow execution"; the `Engine` docstring's "Sequential execution stays deterministic at any shape" is replaced with the actual model (superstep concurrency per LangGraph; determinism comes from compile-checked equal-depth joins, declaration-ordered collects, and single-sender dispatch).

`packages/ngen-weave-core/src/ngen_weave/workflow.py`:

- `_levels` and `_back_edges` move here (validation must not import from `runner.py`; the dependency direction is runner → workflow).
- New join-depth check invoked from `_check_fanin`'s multi-parent path (or as a sibling check in `_check_topology`): every multi-parent target's ordinary static parents must share one longest-path level. START pseudo-parents are exempt — they deliver the seeded input before any node runs and never race a join. Violation raises `ConfigError` naming the target, the parent names, and their depths, with a pointer to `plans/design/loops-and-joins.md`.

Note on counting: relay nodes never emitted `node_activation` records (their node functions write nothing), so `Budget.steps` counting and the Branch B docstring are unaffected by this removal.

Tests: two existing unequal-depth fan-in tests in `engine/test_engine.py` are converted to compile-error assertions: `test_named_slot_fanin_assembles_inputs` (parents at depths 1 and 2 feeding one synth) and `test_collected_fanin_assembles_list_field` (the textbook relay diamond: r1→r2, r1→r3, all three → reducer). `test_nested_composites_fan_in_collected` in `test_nesting.py` is equal-depth (both branch chains are one worker deep) and stays legal — it remains the equal-depth completion exemplar; no conversion.

### Step 7: single-parent retry loops; forbid joins in looping graphs

`packages/ngen-weave-core/src/ngen_weave/workflow.py`:

- `_check_fanin`'s static+conditional prohibition narrows to multi-parent targets: `if len(ordinary) > 1 and dst in dispatched` raises (message updated: "join freshness is not defined for loops"). Single-static-parent targets may receive conditional edges. Assembly needs no runtime change: `_plan_form` already classifies by static parents, so the compiled form stays `"single"` and `plan.setdefault` never overrides it with dispatch — a conditional re-entry fires the node on its static parent's last written output (retry semantics).
- New loop-join guard: a wiring containing any back edge (over static and conditional edges, DFS from START — the `_back_edges` algorithm moved here) forbids multi-parent static targets entirely. Multi-parent target in a looping graph raises `ConfigError` naming the target and the back edge. Together with the equal-depth check this gives a clean split: acyclic graphs allow equal-depth multi-parent fan-in; looping graphs allow single-parent shapes only (retry loops stay legal there).

### Step 8: execution docs rewrite

`docs/engine/execution.md`:

- The "Depth alignment: relay nodes" section is replaced by "Supported shapes in 0.2.x": conditional re-entry and retry semantics (a node fires when any trigger arrives; a retried node reads its static parent's last output), equal-depth fan-in with the compile guarantees, dispatch. The record-ordering guarantee is stated: per-node total order, cross-node order within one superstep unspecified.
- Known-limitations section: concurrent dispatch senders (last-wins `__ngen_last__` delivery is nondeterministic), terminal selection under concurrent fan-out to END (recorded output is completion-order dependent), join freshness in loops (forbidden by validation) — each pointing at `plans/design/loops-and-joins.md`.

`plans/design/loops-and-joins.md` (new): the deferred design — why relays were removed, join freshness semantics, dispatch delivery options, scheduling policy question, terminal selection. Authored with this amendment; Branch D must not change its scope, only reference it.

Tests (new file `engine/test_loops.py`): `test_midchain_retry_loop_completes` (START→A→B→G control with a decide counter retrying B, then done→T→END; asserts completion and B's repeated activations), `test_diamond_fan_in_compile_error` (asserts the ConfigError names target and depths), `test_equal_depth_fan_in_still_completes`, `test_multi_parent_join_in_loop_compile_error` (multi-parent target plus any back edge), `test_capped_loop_pauses` (control that always retries under `Budget(steps=N)`; run pauses at the cap deterministically rather than spinning).

Out of scope: dispatch delivery changes (no slots mechanism), terminal-selection mechanism change (no single-terminal rule), join freshness semantics, new builder vocabulary, observer/budget behavior changes, removing the `__ngen_last__` channel (dispatch targets and output selection still read it).

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine -q`; `uv run pytest -q`; `uv run ruff check .`.
