# ngen-weave v0.2.1 implementation plan

Status: ready to implement.

## Context

v0.2.0 shipped RunService serving (FastAPI + MCP), SQLite storage, budgets, observers, and AgentNode, all merged to main. The post-merge evaluation found one real defect (per-Engine drive state shared between concurrent drives) and several small robustness and consistency gaps. This patch lands fixes only; no features, no protocol changes.

Files touched: `engine/runner.py`, `engine/store.py`, `config.py`, `wiring.py`, a new `local_service.py` in core, the local-service tests moved into core, `tests/conformance/test_run_service.py`, `tests/e2e/test_v02_criteria.py` (import line only), five `pyproject.toml` files.

Depends on: nothing new. Fixes trace to the v0.2.0 review findings. Governing docs if more detail is ever needed: `plans/releases/v0.2.md`, `plans/design/artifact-store.md`, `plans/design/constants.md`.

## Goals

1. Two runs driven concurrently by one Engine cannot corrupt each other's outcomes.
2. Cancellation survives status races between peek and set.
3. One malformed legacy run file cannot prevent store or server startup.
4. `LocalRunService` stops depending on the server package, so stdio/MCP-only installs genuinely avoid FastAPI (closing the F1 gap flagged in review).
5. Pin `RunSummary.cost_usd` accuracy in the conformance suite and document exact `Budget.steps` counting semantics.

## Branch A — engine correctness (`fix/v021-engine`)

### Step 1: isolate per-drive outcome state

`Engine._drive` currently resets three instance attributes at the start of every drive and reads them again in `_resolve_outcome`: `self._waiting`, `self._boundary_stop`, `self._breach_emitted` (declared near `__init__`'s `_cancel_flags`; reset at the top of `_drive`). When two drives overlap behind `LocalRunService`, drive B's reset erases drive A's pause/cancel decision. Fix this by making the triple a value owned by one drive.

Contract. In `packages/ngen-weave-core/src/ngen_weave/engine/runner.py`:

```python
@dataclass
class _DriveState:
    """Outcome bookkeeping for exactly one drive of one run."""

    waiting: dict | None = None  # set by the emitter on waiting_human
    boundary_stop: dict | None = None  # outcome of the last boundary breach
    breach_emitted: set[str] = field(default_factory=set)  # runs whose budget record landed
```

Thread one `_DriveState()` instance created at the top of `_drive` through every method that reads or wrote the old attributes:

- `_drive` and `_resolve_outcome(compiled, final)` become `_resolve_outcome(state, compiled, final)`.
- `_at_boundary(run_file, node_path, metadata)` becomes `_at_boundary(state, run_file, node_path, metadata)`.
- `_observe_boundary` takes `state` the same way (its pause path writes `boundary_stop`).
- The record emitter factory `_emitter(run_id, node_path)` becomes `_emitter(state, run_id, node_path)`; its closures write `state.waiting`.
- Every other write/read site found by `grep -n "_waiting\\|_boundary_stop\\|_breach_emitted" runner.py` moves to the passed-in state.

Delete the three attributes from `__init__`. `self._cancel_flags` stays an Engine-level `set[str]` deliberately: cancel requests must be visible to whichever drive is running that run id. Add one comment beside it saying so.

Reads of `self._latest_waiting(run_file)` and the resumed-seed path are unrelated; leave them alone.

Regression test. New file `packages/ngen-weave-core/src/ngen_weave/engine/test_drive_isolation.py`, following the fakes style of `test_budget.py`:

```python
async def test_concurrent_drives_keep_outcomes_separate() -> None:
```

One Engine, two workflow instances whose configs differ in budget: run A gets `Budget(steps=1)` (must pause at its first boundary carrying a `budget_exhausted` record), run B has no budget (must complete). Launch both with `asyncio.gather(engine.run(...), engine.run(...))` using different run ids. Assert: A's result status `"paused"` with non-None waiting info, exactly one `budget_exhausted` among A's records and none among B's; B's result status `"completed"` with a validated output. Then rerun the whole test body twice inside one session via a loop to catch ordering flakiness. If the fake provider in `fakes.py` cannot express two workflows with distinct budgets on one engine, extend the fake; do not weaken the assertion.

Out of scope: changing when boundaries fire; touching `run.cel`/observer semantics; renaming any public method; converting the driver loop to async pools beyond `gather`.

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine -q` (isolation test green, all prior engine tests green); `uv run pytest -q` overall; `uv run ruff check .`.

### Step 2: race-safe cancellation

`Engine.cancel` decides from a `peek` whether to add a cancel flag or immediately `set_status("cancelled")`. Between peek and set, another actor can finish or resume the run, so a stale immediate-set can land on an unexpected state. Make the status transition conditional in SQL.

Contract. In `packages/ngen-weave-core/src/ngen_weave/engine/store.py`, extend the existing method:

```python
def set_status(
    self, run_id: str, status: RunStatus, expected: frozenset[RunStatus] | None = None
) -> bool:
    """Persist one status column update.

    With expected, the update applies only when the current status is a
    member; returns whether a row changed. Unknown run ids raise
    UnknownRunError either way.
    """
```

Single `UPDATE runs SET status = ? WHERE run_id = ?` plus, when `expected` is given, `AND status IN (...)`; `rowcount == 1` is the return. Import `UnknownRunError` from `ngen_weave.service` (it exists there today).

In `runner.py`, `Engine.cancel` becomes exactly:

```python
def cancel(self, run_id: str) -> None:
    run_file = self.store.peek(run_id)
    if run_file is None:
        raise UnknownRunError(run_id)
    if run_file.status in {"completed", "failed", "cancelled"}:
        return  # already terminal; cancelling again is a no-op
    if run_file.status == "running":
        self._cancel_flags.add(run_id)
        return
    self.store.set_status(run_id, "cancelled", expected=frozenset({"paused", "waiting_human"}))
```

A False return here means the run reached a terminal status in the race window, which is equivalent to the no-op case; do not retry or warn. Also sweep stale flags: in `_drive`, the existing `_cancel_flags.discard(run_id)` runs on the `"cancelled"` branch only; move one unconditional `discard` call so every terminal outcome (completed, failed, cancelled, waiting_human) clears the flag for its run id, and delete the now-redundant discard inside the cancelled branch.

Tests. Extend `packages/ngen-weave-core/src/ngen_weave/engine/test_budget.py` (cancel behaviour lives there today) alongside the existing double-cancel and cancel-between-transitions cases:

- `test_cancel_racing_completion_is_noop`: pause run, drive it to completion out-of-band (resume with raised cap via a second task), call `cancel` after completion; expect no exception, status stays `"completed"`, no `cancelled` record appended.
- `test_set_status_expected_mismatch_returns_false`: direct store-level check of the new contract, including the UnknownRunError path.

Out of scope: cross-process cancellation (the docstring already scopes cancel to same-process); changing who may cancel; any HTTP route changes.

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine -q`; then `uv run pytest packages/ngen-weave-server/tests/conformance packages/ngen-weave-mcp/tests -q` since conformance exercises cancel through every backend.

## Branch B — storage tolerance and budget clarity (`fix/v021-store`)

### Step 3: tolerate malformed legacy run files

> SUPERSEDED pre-1.0: `RunStore._import_legacy` was removed entirely (deliberate no-back-compat
> contract change; see the PRD roadmap serialization bullet). There is no legacy import left to
> make tolerant; the store never scans `.ngen-weave/runs/*.json`. The text below describes work
> that was never merged and is retained only as historical planning record.

`RunStore._import_legacy` raises `ConfigError` from `__init__` when any `.ngen-weave/runs/*.json` fails `load_run_json`, which makes the whole store unusable until someone deletes the file. Import failures are advisory data loss, not configuration failure.

Contract. In `packages/ngen-weave-core/src/ngen_weave/engine/store.py`, add a module logger next to the existing constants (`logger = logging.getLogger(__name__)`) and replace the `raise ConfigError(...)` inside `_import_legacy` with:

```python
logger.warning("skipping legacy run file %s: %s", path, exc)
continue
```

Everything else in the method stands: sort order, idempotent PK skip, `started_at` fallback. The `ConfigError` import stays if other call sites need it; remove it only if unused.

Test. Extend `packages/ngen-weave-core/src/ngen_weave/engine/test_store_sqlite.py`:

```python
def test_malformed_legacy_file_is_skipped(tmp_path, caplog) -> None:
```

Seed the runs dir with one valid exported v0.1 run and one file containing `b"{not json"`; construct `RunStore`; assert the valid run appears in `list()` results, the store constructed at all, and `caplog` captured exactly one warning naming the bad path. Assert idempotence by constructing a second `RunStore` over the same dir with no warnings emitted (caplog empty on the second construction, use `caplog.clear()`).

Out of scope: quarantine directories, retry logic, repair of partially readable files, changing any export/import format.

Verify: `uv run pytest packages/ngen-weave-core/src/ngen_weave/engine/test_store_sqlite.py -q`.

### Step 4: pin cost_usd accuracy and document steps semantics

Two small clarifications that the v0.2 review asked for. They travel together because both are about budget observability.

Contract. Conformance: append to `packages/ngen-weave-server/tests/conformance/test_run_service.py` one test run on every backend fixture:

```python
async def test_list_reports_accurate_cost(service_run_completed) -> None:
```

Drive one workflow to completion through the RunService under test (same fixtures the ordered-record test uses). Compute `expected = sum(float(r.payload.get("cost_usd") or 0.0) for r in (await service.status(run_id)).records if r.kind == "model_call")`. Assert `(await service.list_runs()).cost_usd for that run id` equals `pytest.approx(expected, abs=1e-9)`. No tolerance wider than that; totals columns are maintained incrementally on purpose.

Docstring: in `packages/ngen-weave-core/src/ngen_weave/config.py`, extend the `Budget` docstring's steps sentence to read exactly: "steps caps node_activation counts, counting every activation record including retries, invalid outputs, human interruptions, and scope completions, so a limit trips earlier than successful-node-count intuition suggests."

Out of scope: changing how activations are counted; adding fields to `RunSummary`; touching the summary projection function beyond what the test demands.

Verify: `uv run pytest tests/conformance packages/ngen-weave-server/tests -q`; `uv run pytest packages/ngen-weave-core/src/ngen_weave/test_config.py -q` if such docstring assertions exist there, otherwise the full suite at the end of the branch.

## Branch C — local service relocation (`refactor/v021-local-service`)

### Step 5: move LocalRunService into core, close the install gap

`ngen_weave_server.local.LocalRunService` imports nothing from the server package; it wraps Engine, RunStore, and a discovery map, all core types. Its home in the server package is why `build_service` needs the server installed and why the plan's "stdio-only installs do not pull FastAPI" claim failed review. Move it where it belongs.

Contract. New file `packages/ngen-weave-core/src/ngen_weave/local_service.py`: two-line module header ("in-process RunService over Engine and RunStore") plus the class and its docstrings carried over verbatim from `packages/ngen-weave-server/src/ngen_weave_server/local.py`. Public name stays `LocalRunService`; constructor signature unchanged: `__init__(self, engine: Engine, store: RunStore, discovery_map: dict[str, type[Workflow]]) -> None`.

Delete `packages/ngen-weave-server/src/ngen_weave_server/local.py`. Move its test file to sit beside the new subject: `packages/ngen-weave-server/src/ngen_weave_server/test_local_service.py` becomes `packages/ngen-weave-core/src/ngen_weave/test_local_service.py` with only the import line adjusted.

Update the nine references found by `grep -rn "LocalRunService\\|local import\\|from ngen_weave_server.local" --include="*.py"` to import `from ngen_weave.local_service import LocalRunService`:

- `packages/ngen-weave-core/src/ngen_weave/wiring.py`: `build_service` drops the whole `try/except ImportError` guard and imports directly at function top. Its docstring loses the "imported lazily" sentence and gains none in exchange.
- `packages/ngen-weave-server/src/ngen_weave_server/app.py`, `mcp/src/ngen_weave_mcp/http.py`, `mcp/src/ngen_weave_mcp/test_tools.py`, `server/tests/conformance/conftest.py`, `server/tests/conformance/test_review_parity.py`, `tests/e2e/test_v02_criteria.py`: mechanical import-line updates, nothing else.
- The two test files listed above.

Docstring policy from `plans/implementation/README.md` applies: update the two-line purpose wherever the module story actually changed (`wiring.py`, `app.py`).

Confirm the boundary afterwards: `grep -rn "^from ngen_weave\\|^import ngen_weave" packages/ngen-weave-core/src/ngen_weave/local_service.py` shows only core imports, and nothing outside `ngen_weave_server/{app,client}.py` mentions fastapi.

Out of scope: keeping a deprecation shim (pre-1.0, internal only); moving the HTTP client; touching `RunService` Protocol; deciding extra/dependency groups in pyprojects beyond deleting nothing (no dependency edits needed here, that falls out naturally and version bump comes later).
