# v0.6 implementation plan

## Context

After v0.5 (`implementation/v0.5.md`: plugins, notification reference plugins, boxed agent autonomy) all ngen-weave state is local: `SqliteRunStore` writes runs and provenance records into `.ngen-weave/runs.db` (v0.2 A2), `DefinitionStore` writes definition files (v0.4), `VersionLog` writes sidecar manifests next to content-addressed blobs (v0.4), and the notification dispatcher keeps dedupe state in a JSON file (v0.5).

v0.6 adds the platform layer and nothing else: Postgres becomes canonical for run state, provenance records, artifact manifests, and workflow registrations, with SQLAlchemy 2.0 async and Alembic from day one. Artifact blobs stay content-addressed on disk joined by hash. File mode stays the zero-config local default. Auth, roles, multi-reviewer human nodes, tickets, and `import-project` are v0.8; identity never touches this release.

Files touched:

- `packages/ngen-weave-core/src/ngen_weave/db/` (**new**): engine factory, ORM tables, Postgres repos under `stores.py`
- `packages/ngen-weave-core/alembic/` (**new**) and `packages/ngen-weave-core/alembic.ini`
- `packages/ngen-weave-core/src/ngen_weave/config.py`: optional `database:` key
- `packages/ngen-weave-core/src/ngen_weave/engine/store.py`, `runner.py`, `definitions.py`, `artifacts.py` (VersionLog), `notify.py`: async conversion, protocol extraction
- `packages/ngen-weave-core/src/ngen_weave/export.py`: gains nothing itself; `PgRunStore` joins its writer in Branch D
- `packages/ngen-weave-server/src/ngen_weave_server/app.py`, `service.py`: backend selection
- `packages/ngen-weave-cli/src/ngen_weave_cli/context.py`, `main.py`: backend selection, `ngen-weave db upgrade`

Depends on: `releases/v0.6.md` (requirements), `product/PRD.md` (decision log, wins on conflict). Store shapes come from `implementation/v0.2.md` A2 (SqliteRunStore, export writer), `implementation/v0.4.md` (DefinitionStore, VersionLog), and `implementation/v0.5.md` (NotificationDispatcher); this plan references them and never restates their reasoning.

Conventions inherited from `implementation/v0.1.md` and later plans: Python ≥3.12, uv workspace, pytest, ruff, conventional commits, one commit per step unless stated, full suite green before committing, tests next to code except e2e under `tests/e2e/`, fakes over live services, no network except live-marked tests.

Global out of scope for every step (per `releases/v0.6.md` non-goals): token auth and roles, multi-reviewer human nodes, tickets, `import-project`, multi-tenancy beyond projects-per-user, SSO/OIDC, live collaborative editing, distributed execution, object-storage blob backends beyond the hash-keyed disk layout, API semver (that is 1.0), dropping file mode.

---

## Goals

1. A server deployment pointed at an empty Postgres database reaches working state through `alembic upgrade head` alone.
2. Any run in either backend exports to the same single-file run-JSON bytes through the one writer `dump_run_json` (`export.py`, v0.2).
3. File mode survives untouched: `ngen-weave run` with no database config behaves exactly as v0.5.

## Success criteria

From `releases/v0.6.md`, tested not promised:

1. Fresh-deployment e2e: empty Postgres, `db upgrade`, launch and complete a run, rows exist. No manual SQL anywhere.
2. Export parity: identical run through each backend produces byte-identical `dump_run_json` output, equal to recorded pre-v0.6 fixture bytes.
3. Every pre-v0.6 suite passes with no database and no test edits beyond adding `await`.

## Abstractions and what they absorb

One sentence each.

- **One `database:` config key resolving to a store-construction site per store kind** absorbs future backends: callers already take abstract stores, so a new backend means one factory branch, not caller changes.
- **Async store protocols converted once in Branch B** absorb the Postgres backend without a second ripple: after Branch B no caller cares whether IO is files or wire.
- **Verbatim JSONB payloads keyed by ordinal** (runs metadata aside) absorb record-shape churn through 1.0, which the PRD guarantees: record changes touch the dataclasses, never a migration.
- **`dump_run_json(run: RunFile) -> bytes` as the single serializer** absorbs every export question permanently: byte parity holds because there is exactly one writer, shared since v0.2.
- **A `NotifyState` key-value protocol** absorbs new dispatcher state fields (another field in the state dict) and object-storage-backed state (another class implementing two methods).

## Branch map and decision tree

Four branches, six steps. Parallelism and bottlenecks:

```
Branch A: Step 1 (schema + engine factory)      ─┐
Branch B: Step 2 (async store protocols)         ├─ both feed everything below;
                                                 │   A and B are independent of each
                                                 │   other and run in parallel
                                                 ▼
Branch C: Step 3 (PgRunStore + backend selection)
              ├──► Step 4 (remaining PG repos)          # C then D, sequential: both edit
              │                                          # the same two selection sites
              └──► Branch E: Step 5 (export parity)     # needs Step 3 only; can start
                                                         # while Step 4 is in flight if
                                                         # Step 4 lands second
                                                         ▼
                       Step 6 (success-criteria e2e + docs)   # needs 3, 4, 5
```

- Steps 1 and 2 touch disjoint files. Run them in parallel.
- Steps 3 and 4 both edit `_build_engine` and `create_app`, so one writer: 3 first, 4 rebase-landed after. Within Step 3 the repo classes are stubbed as pass-throughs so 3 stays shippable alone.
- Step 5 needs only Step 3. It may proceed during Step 4.
- Nothing merges to main inside this release cycle; branches stack on the release integration branch in the order 1, 2 (either order), 3, then 4 and 5 in parallel, then 6.

## Branch A: Database foundation

### Step 1: Engine factory, tables, initial migration

New: `packages/ngen-weave-core/src/ngen_weave/db/__init__.py`, `db/engine.py`, `db/tables.py`; `packages/ngen-weave-core/alembic.ini`, `packages/ngen-weave-core/alembic/env.py`, `alembic/versions/0001_initial.py`. Extended: `packages/ngen-weave-core/src/ngen_weave/config.py`, `pyproject.toml` of `ngen-weave-core`.

Dependencies added to core runtime: `sqlalchemy[asyncio]>=2.0`, `asyncpg`, `alembic`, `psycopg[binary]` (sync driver Alembic uses). Dev: `aiosqlite`, `greenlet`.

Contracts, fixed here (`db/engine.py`):

```python
def resolve_database_url(config: ResolvedConfig, env: Mapping[str, str] | None = None) -> str | None:
    """env["NGW_DATABASE_URL"] wins; else config.database["url"]; else None (file mode)."""

def create_db(url: str) -> AsyncEngine                      # create_async_engine(url, pool_pre_ping=True)
def make_sessionmaker(engine: AsyncEngine) -> async_sessionmaker[AsyncSession]
def to_sync_url(url: str) -> str                            # postgresql+asyncpg:// -> postgresql:// ; Alembic only
```

Config (`config.py`): optional top-level `database:` accepting exactly `{url: str}`; unknown keys rejected by the existing rules; `ResolvedConfig` gains `database: dict = field(default_factory=dict)`.

Tables (`db/tables.py`, declarative `Base`). Columns mirror the post-v0.5 `RunFile` and the v0.2 SQLite layout field-for-field; anything not a column rides inside the JSONB payloads. No auth/role/ticket tables; v0.8 adds its own migrations.

- `runs`: `run_id` str PK; `workflow` str; `status` str (includes `"cancelled"`, set by v0.2 B2); `input` JSONB; `output` JSONB null; `error` JSONB null; `attempts` int default 0; `submissions` JSONB default `{}`; `started_at` str null; `notes` JSONB default `[]`; `cost_usd` numeric default 0; `activations` int default 0; `budget` JSONB null; `budget_override` JSONB null; `created_at` timestamptz server default now; `updated_at` timestamptz onupdate.
- `records`: `run_id` str FK `runs.run_id` on delete cascade; `seq` int (ordinal in the stream, unique with `run_id`); `ts` str; `node_path` str; `kind` str; `payload` JSONB stored verbatim. The dataclasses in `provenance.py` remain the only schema authority; this table never gets a column for a payload field.
- `definitions`: `name` str PK; `text` text (exact file bytes decoded, same contract as `DefinitionRecord.text`); `updated_at` timestamptz.
- `artifact_versions`: `project` str; `name` str; `version` int; `sha256` str; `ts` str; `run_id` str; `node_path` str; PK `(project, name, version)`. Blob bytes stay out of the database permanently (`design/artifact-store.md`); sha256 is the join key to disk.
- `notify_state`: `rule_name` str; `run_id` str; `state` JSONB; PK `(rule_name, run_id)`.

Alembic: `env.py` reads `NGW_DATABASE_URL` through `to_sync_url`; application code never runs migrations, deployment does (Step 3 wires the CLI verb).

Tests (`db/test_engine.py`, `db/test_migrations.py`): resolution precedence env > config > None; `to_sync_url` round trips both driver forms; config rejects unknown keys inside `database:`; migration test runs `upgrade head` against empty Postgres when `NGW_TEST_DATABASE_URL` is set (`live` marker, skipped otherwise) and asserts every table exists; a `sqlite+aiosqlite` variant runs `Base.metadata.create_all` giving Steps 3–4 a network-free backend with identical DDL.

Out of scope: any store reading or writing these tables (Steps 3–4), seeding, pool tuning, downgrade paths beyond the generated stub, an async migration runner.

Verify: `uv run pytest src/ngen_weave/db/ src/ngen_weave/test_config.py && uv run ruff check .`. With docker: `NGW_TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/ngw_test uv run pytest -m live src/ngen_weave/db/test_migrations.py`.

## Branch B: Async store seam

### Step 2: Stores go async: mechanical conversion, zero behavior change

Touch `packages/ngen-weave-core/src/ngen_weave/engine/store.py`, `runner.py`, `definitions.py`, `artifacts.py` (VersionLog), `notify.py`, and every caller: `Engine`, `LocalRunService` and `HttpRunService` (`server/service.py`), `NotificationDispatcher.scan_once`, CLI context and commands, readmodel loaders. This step exists so Steps 3–5 land with no call-site ripple.

Contract changes, applied mechanically:

- `RunStore` renames to `SqliteRunStore` with `RunStore = SqliteRunStore` alias kept for one release. All seven methods become `async def`: `create`, `load`, `save`, `append`, `set_status`, `list`, plus the file-based `save_review_artifact` / `read_review_artifact` (they stay file-based in every mode, per v0.2 A2).
- A formal protocol lands in `engine/store.py`; Steps 3–5 implement against it:

```python
class RunRepo(Protocol):
    async def create(self, workflow_name: str, input_dump: dict) -> str: ...
    async def load(self, run_id: str) -> RunFile: ...          # unknown id -> UnknownRunError
    async def save(self, run_file: RunFile) -> None: ...
    async def append(self, run_id: str, record: ProvenanceRecord) -> None: ...
    async def set_status(self, run_id: str, status: RunStatus) -> RunFile: ...
    async def list(self, *, workflow: str | None = None,
                   status: str | None = None) -> list[RunFile]: ...

class DefinitionRepo(Protocol):
    async def list(self) -> list[DefinitionRecord]: ...
    async def load(self, name: str) -> type[Workflow]: ...
    async def save(self, data: dict) -> type[Workflow]: ...
    async def delete(self, name: str) -> None: ...
    async def raw(self, name: str) -> str: ...

class VersionLogRepo(Protocol):
    async def append(self, name: str, sha256: str, ts: str,
                     run_id: str, node_path: str) -> VersionEntry: ...
    async def entries(self, name: str) -> list[VersionEntry]: ...
```

- Error types unchanged: unknown run raises `UnknownRunError` (v0.2), missing definition raises the existing ConfigError, both from the concrete stores exactly as today.
- Callers updated in place: same signatures outside these modules, awaited internals. `scan_once` becomes `async def scan_once`.

Deliberately untouched: `RunFile` shapes, atomic-write mechanics, provenance emission, file formats, SQLite schema, totals maintenance (`cost_usd`, `activations`) inside `append`.

Tests: none new. The whole existing suite passes unmodified except adding `await` where fixtures drive stores directly. If any assertion needs a behavioral change, this step did something wrong; revert that edit.

Absorbs: the entire Postgres rollout and any future remote store.

Out of scope: any Postgres code, batching, write-behind caching, renaming aliases beyond the one kept.

Verify: `uv run pytest -m 'not live' && uv run ruff check .`, results identical to the pre-step baseline.

Commit: `refactor(core): store protocols go async ahead of postgres`

PR title: **Async store protocols: mechanical conversion ahead of the Postgres backend**

## Branch C: Runs and records in Postgres

### Step 3: PgRunStore and backend selection

New: `packages/ngen-weave-core/src/ngen_weave/db/stores.py`. Edited: `packages/ngen-weave-cli/src/ngen_weave_cli/context.py` (`_build_engine`), `packages/ngen-weave-server/src/ngen_weave_server/app.py` (`create_app`), `main.py` of the CLI (`ngen-weave db upgrade`), core dev deps gain `langgraph-checkpoint-postgres`.

```python
class PgRunStore:
    """RunRepo over the runs + records tables. One session per method call."""
    def __init__(self, sessionmaker: async_sessionmaker[AsyncSession]) -> None
    # Methods match RunRepo exactly; semantics match SqliteRunStore:
    #   create  -> uuid4 id, INSERT initial row, return id
    #   load    -> SELECT row + records ordered by seq; rebuild RunFile
    #              (unknown id -> UnknownRunError)
    #   save    -> UPDATE non-record fields; records are insert-only through
    #              append, matching the file invariant that only append touches
    #              the stream
    #   append  -> INSERT with seq = max(seq)+1 for the run, in the same
    #              transaction as the totals update (model_call cost ->
    #              cost_usd, node_activation -> activations), mirroring v0.2 A2
    #   set_status / list -> direct row equivalents of the SQLite versions;
    #              list loads headers only, never the stream
```

Backend selection lives in exactly two places:

- CLI `_build_engine`: after config resolution, `url = resolve_database_url(config, os.environ)`; when set, build engine and sessionmaker, construct `PgRunStore`, pass-through `DefinitionRepo`/`VersionLogRepo` (the current file classes, until Step 4 swaps them), and use `AsyncPostgresSaver` as the LangGraph checkpointer with the same URL; thread id stays the run id (v0.2 identity decision, unchanged). When unset, current classes and behavior, byte-identical.
- Server `create_app(..., database_url: str | None = None)`: resolution order argument, env, config; same branch; expose `app.state.store_mode` ("file" | "postgres").

Startup guard: in Postgres mode both sites run one `SELECT 1 FROM runs LIMIT 1` at startup and raise `InfraError("database not migrated; run: ngen-weave db upgrade")` on failure.

CLI plumbing: `ngen-weave db upgrade` invokes Alembic programmatically (`alembic.config.Config` pointed at the package's `alembic.ini`, `command.upgrade(head)`) using `to_sync_url` on the resolved URL; errors when no URL resolves.

Tests (`db/test_run_store_pg.py`): one parametrized suite driving `create/load/save/append/set_status/list` round trips, mid-transition kill (only committed transactions survive), record ordering, header-only `list`, and error contracts against both `SqliteRunStore` (tmp db) and `PgRunStore` (aiosqlite sessionmaker). Live-marked repetition under real Postgres.

Absorbs: future run-store backends (implement `RunRepo`, add one branch at each selection site) and payload-shape evolution (dataclass change only, per the JSONB policy).

Out of scope: definitions/versions/notify-state being written from Postgres (Step 4; selection sites reference the file implementations until then), pooling configuration surface, read replicas, search over records, migrating existing file-mode projects (that is v0.8 `import-project`).

Verify: `uv run pytest src/ngen_weave/db/ packages/ngen-weave-server/ packages/ngen-weave-cli -m 'not live'`. Manual: point `NGW_DATABASE_URL` at an empty database, `uv run ngen-weave db upgrade && uv run ngen-weave run examples/code_review/ngw.yaml`, confirm rows in `runs` and `records` and a completed status.

### Step 4: Definitions, artifact versions, notify state

```python
    """NotifyState over notify_state."""
    def __init__(self, sessionmaker: async_sessionmaker[AsyncSession]) -> None
```

Dispatcher state generalization (`notify.py`): extract today's JSON-file logic verbatim into `FileNotifyState` and define

```python
class NotifyState(Protocol):
    async def load(self, rule_name: str, run_id: str) -> dict | None: ...
    async def save(self, rule_name: str, run_id: str, state: dict) -> None: ...
```

`NotificationDispatcher.__init__` parameter `state_path: Path` widens to `state: NotifyState`; the dispatcher learns nothing about either implementation. Selection sites pass `FileNotifyState(root)` in file mode and `PgNotifyState(sessionmaker)` otherwise.

Decisions:

- Artifact blobs stay content-addressed on disk in Postgres mode too, same configured root (`design/artifact-store.md`). Only manifests join the database; no path changes anywhere because sha256 is the join key.
- `PgVersionLog` carries `project` because the table keys on it; file-mode `VersionLog` derives project from its directory layout as today. Both read the same config field.
- Grep-enforced single-import rule: a unit test asserts `db.stores` is the only module importing both `sqlalchemy` and any repo protocol, so backend branching cannot scatter.

Tests (`db/test_repos_pg.py`): each class against aiosqlite mirroring its file-mode suite's cases: definition round trip, registered-Python collision rejection, delete, raw; version ordering and crash safety; notify fire-once surviving a restart with `PgNotifyState`; live-marked repetition under real Postgres.

Absorbs: object-storage manifests later (another `VersionLogRepo` implementation) and additional dispatcher state (fields in the state dict, no protocol change).

Out of scope: blob bytes in the database, serving definitions from both backends at once, automatic migration of live file-mode projects, backup tooling.

Verify: `uv run pytest src/ngen_weave packages/ngen-weave-server packages/ngen-weave-cli -m 'not live' && uv run ruff check .`

## Amendments to earlier plans

Kept explicit, per the convention earlier plans set:

1. **Stores** (v0.2 A2, v0.4, v0.5 Step 6): all go async in Step 2 with identical semantics; `RunStore` renames to `SqliteRunStore` keeping an alias; `export` joins `RunRepo` in Step 5. Formats and schemas unchanged.
2. **`NotificationDispatcher`** (v0.5): `scan_once` becomes async (Step 2); `state_path` generalizes to `NotifyState` (Step 4); rule and fingerprint logic untouched.
3. **`ResolvedConfig`** (v0.1 Step 5, widened since): gains `database: dict` (Step 1); unknown-key rejection applies inside it as everywhere.
4. **`create_app`** (v0.2, widened since): gains the defaulted `database_url` keyword (Step 3); file-mode open-local behavior preserved.
5. **LangGraph checkpointer choice** (v0.1): Postgres mode selects `AsyncPostgresSaver`; thread-id-equals-run-id stands.
6. **No semantic drift allowed downstream.** If a step appears to alter validation, provenance emission, artifact addressing, or envelope shapes, stop: the JSONB payload policy exists precisely so record shapes evolve without touching this release's schema again.
