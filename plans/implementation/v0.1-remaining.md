# v0.1 remaining work: branch plan

Everything left after the `feat/cli-commands` branch exists, updated against
the actual tree. Source of truth: `releases/v0.1.md`,
`implementation/v0.1.md` (Steps 12–13 plus the definition of done). One
branch per feature, one branch per context window. Every branch leaves the
repo green: `uv sync && uv run ruff check . && uv run pytest -m 'not live'`.

## Where things actually stand

Merged to master (`f720e3c`, the feat/config merge): workspace scaffold,
error taxonomy, provenance envelope, workflow base classes with import-time
validation, discovery, config layer, model layer — Steps 1–6 of
implementation/v0.1.md.

On branches, unmerged:

- `feat/artifacts` carries Steps 7–11: engine compile/run/retry, run store,
  recursive composition with cost attribution, human interrupts with review
  artifacts, content-addressed artifact store. Master has none of it.
- `feat/cli-commands` carries Step 12: four commands, `context._build_engine`
  seam, 14 CLI tests, `docs/cli.md`. It branched from the same commit as
  `feat/artifacts`, so its imports of `ngen_weave.engine` resolve only once
  artifacts merges too.

Three gaps found by inspection, each owned by a branch below:

1. Merging both branches touches `docs/README.md` at the same anchor line;
   the rest merges clean (verified with `git merge-tree`: one hunk).
2. `worktrees/v0.1` still has `feat/engine-flat` checked out. Running pytest
   from the repo root collects that tree and errors out. The worktree goes
   away during merge housekeeping.
3. `run_command` parses `--project` but discards it, and `_build_engine`
   never builds an `ArtifactStore`. Declared `artifacts` therefore persist
   nothing through the CLI, and no e2e test can assert content-addressed
   outputs until that is fixed. Owned by Branch 1.

## Branch 1 — `fix/cli-artifact-store`

Wire the artifact store through the CLI so declared `artifacts` actually
persist. Core stays frozen.

Deliverables:

- `context.py`: `AppContext` gains an `artifacts: ArtifactStore | None`;
  `_build_engine(config, provider=None, project=None)` constructs
  `ArtifactStore(NGEN_WEAVE_DIR / "projects", project or "default")` and
  passes it to `Engine(..., artifacts=...)`. Resume and status keep passing
  none; they never write blobs.
- `main.py`: `run_command` forwards its `project` option into
  `_build_engine`.
- Tests in `test_cli.py`: a workflow declaring an artifact produces a blob
  under `.ngen-weave/projects/<project>/` with a sidecar, driven through
  Typer's runner with FakeProvider.

Verify: `uv run pytest packages/ngen-weave-cli/tests/ && uv run ruff check .`

Commit: `fix(cli): construct ArtifactStore from --project so declared artifacts persist`

## Branch 2 — `feat/example-code-review`

Steps: example package first, then the happy-path test, then interrupt/

## Sequencing

Strictly linear. Each branch depends on the previous one's merge:

```
merge feat/artifacts + feat/cli-commands → master   (Branch 0)
  └─ fix/cli-artifact-store
       └─ feat/example-code-review
            └─ feat/example-doc-draft
                 └─ test/e2e-nesting-provenance
                      └─ docs/v01-closeout → tag v0.1.0
```

Rationale for the order:

- The merges come first because every later branch tests code whose imports
  only resolve on the combined tree.
- The artifact-store fix precedes the examples because code_review's e2e
  asserts a persisted reviewed diff; without Branch 1 that assertion cannot
  pass at any effort level.
- Code review before doc draft because it is canonical and carries the
  harder tests (interrupt/resume, artifacts, staleness).
- Nesting e2e after both examples because its fixture wraps code_review's
  chain.
- Closeout last because checking off release requirements needs everything
  else merged.

Each branch fits one context window: Branches 0 and 5 touch no logic;
Branch 1 is one module plus a few tests; Branches 2–4 are one package or
fixture set plus one test file each, internally committed in steps small
enough that losing a window costs one step, not the branch.
