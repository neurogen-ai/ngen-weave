# v0.1 remaining work: branch plan

Covers everything left after `feat/artifacts` merges. Source of truth:
`releases/v0.1.md`, `implementation/v0.1.md` (Steps 12–13), and the
definition of done at the end of that plan. One branch per feature, one
branch per context window. Every branch leaves the repo green:
`uv sync && uv run ruff check . && uv run pytest -m 'not live'`.

## Branch 0 — merge `feat/artifacts`

Not a feature branch; the merge that unblocks the rest.

```
git checkout master
git merge --no-ff feat/artifacts
uv run pytest -m 'not live'   # confirm green on master
git push origin master
```

Also delete the consumed branches (`feat/engine-flat`, `feat/engine-nested`,
`feat/human-nodes`) once merged; keep `feat/artifacts` until CI passes on
master.

Step 10 of the v0.1 plan is a no-op verification folded into the nesting
tests that already live on this branch; nothing to do beyond confirming the
six-field metadata assertions pass.

## Branch 1 — `feat/cli-commands`

Implements implementation/v0.1.md Step 12 in full. Nothing else changes;
core is frozen for this branch.

Deliverables:

- `packages/ngen-weave-cli/src/ngen_weave_cli/context.py`: `_build_engine(config)`
  constructing Engine + RunStore + ArtifactStore from `ResolvedConfig`. Single
  construction point so commands stay thin and tests monkeypatch the provider here.
- `main.py` grows the four commands:
  - `ngen-weave validate <config-or-module>` — module path goes through
    discovery (structural validation fires); config file goes through
    `load_config` plus JSON Schema resolution of `input_type`. Exit 1 on any
    `ConfigError`, message on stderr.
  - `ngen-weave run <workflow> [-i input.json] [-c config.yaml] [--project <name>]`
    — resolve through the merged discovery map, print run id, stream final status.
    `-c` wins over `-i`.
  - `ngen-weave resume <run-id> [-p response.json]` — exit 0 only on terminal
    completed/failed; print status either way.
  - `ngen-weave status <run-id>` — workflow, status, waiting-on node path and
    artifact path when `waiting_human`, cost summed from `model_call` records.
- Tests in `packages/ngen-weave-cli/tests/test_cli.py`, driven via Typer's test
  runner with tmp directories and the shared `tests.fakes.FakeProvider`.

Verify: `uv run pytest packages/ngen-weave-cli/tests/ && uv run ngen-weave --help`.

Commit: `feat(cli): validate, run, resume, status commands`

## Branch 2 — `feat/example-code-review`

First canonical example plus the e2e tests that exercise it directly.
Branches off master after Branch 1 merges (the e2e suite drives the CLI).

Deliverables:

- `examples/code_review/`: installable package with `pyproject.toml`
  declaring an entry under the `ngen-weave.workflows` group, `workflows.py`,
  `models.json`, `ngw.yaml`, `request.json` fixture.
- Workflow shape per releases/v0.1.md: `ReviewRequest`/`ReviewState`/`ReviewedDiff`
  models; `draft` Worker with prompt template over `{request.diff}`; `gate`
  Control with programmatic `decide`; `human_review` Human with
  `state_type = ReviewState` (`verdict: Literal["approve","reject"]`, `notes`)
  prefilled from gate context; `finalize` Worker with
  `artifacts = ("reviewed_diff",)`. Wiring matches the release doc's `build()`.
- E2E tests in `packages/ngen-weave-core/tests/e2e/test_code_review.py`,
  FakeProvider wired via the `_build_engine` seam:
  1. full run completes; reviewed diff exists content-addressed with linked provenance
  2. kill-and-resume: interrupt at human review, fresh process state,
     `resume <id> -p response.json` completes correctly
  3. staleness: renamed class in a copied example makes `validate` exit 1

Verify: `uv run pytest packages/ngen-weave-core/tests/e2e/` and manually run
the CLI against the example.

Commit: `feat(examples): canonical code review with e2e coverage`

## Sequencing

Strictly linear. Each branch depends on the previous one's merge:

```
merge feat/artifacts → master
  └─ feat/cli-commands
       └─ feat/example-code-review
            └─ feat/example-doc-draft
                 └─ test/e2e-nesting-provenance
                      └─ docs/v01-closeout → tag v0.1.0
```

Rationale for the order:

- CLI before examples because every e2e test drives the real CLI; building
  examples first would mean rewriting their run instructions later.
- Code review before doc draft because it is canonical and carries the
  harder tests (interrupt/resume, artifacts, staleness).
- Nesting e2e after both examples because its fixture wraps code_review's chain.
- Closeout last because checking off release requirements needs everything else merged.

Each branch fits one context window: Branch 1 is one module plus one test
file; Branches 2–4 are one package plus one test file each; Branch 5 is docs
only.
