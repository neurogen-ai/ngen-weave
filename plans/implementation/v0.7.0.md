# v0.7 implementation plan

## Context

After v0.6 the platform layer is real: Postgres-backed stores with file mode as local default.

v0.7 finishes: external document links land, and named debt gets paid before 1.0's semver freeze.

Depends on: `releases/v0.7.md`, `product/PRD.md`, and module shapes from `implementation/v0.1.md` through `implementation/v0.6.md`. Conventions inherited unchanged.

## Steps

### Step 1 — External document links

`packages/ngen-weave-core/src/ngen_weave/extdoc.py`: one pydantic model (`ExternalDoc`: provider, url, title, accessed-at); definitions serialize it through the standard JSON Schema representation with no format change. Read-model and detail views render links; provenance records reference the link with no content claims. Validation checks URL shape and provider name against a small registry of known providers, with unknown providers accepted but flagged in validation output.

Tests: storage round trip, read-model exposure, provenance record shape, UI detail rendering (web repo).

Commit: `feat(core): external document link references`

### Step 2 — Debt and deprecation sweep

Named at implementation time from a review pass over v0.5/v0.6 leftovers: half-migrated surfaces, docs lagging the database surfaces, deprecated flags to remove before 1.0 freezes semver. Each item lands with its own commit; anything that turns out to need real design work is either scoped into 1.0 explicitly or deferred past 1.0 with a decision record.

Commit series: per item.

## Definition of done

Both success criteria from `releases/v0.7.md` demonstrably pass: external docs validate, render, and export; no undocumented deprecated surface survives into 1.0.
