# v0.1.1 implementation plan

## Context

ngen-weave v0.1.0 ships durable human-in-the-loop LangGraph workflows
(`packages/ngen-weave-core`, `packages/ngen-weave-cli`). During review, a
latent compile-cache collision was found in `Engine`: `_compile_uncached`
recomputes the cache key without `outer_scopes`, so two compilations of the
same workflow class under different nesting scopes return the wrong cached
graph. This plan implements the fix, its regression test, and the version
bump.

Files touched:

- `packages/ngen-weave-core/src/ngen_weave/engine/runner.py` — the fix
- `packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py` — regression tests
- `packages/ngen-weave-core/pyproject.toml`, `packages/ngen-weave-cli/pyproject.toml` — version bump

Depends on: `../releases/v0.1.1.md` (the requirements; read it first for
the full bug analysis). No `design/` doc governs the engine's compile cache;
the key contract is defined inline in `Engine.compile`'s docstring in
`runner.py`.

## Goals

1. `_compile_uncached` uses the caller-supplied `key`; no local recomputation.
2. A regression test that fails on v0.1.0 code and passes after the fix,
   proving both directions: distinct keys yield distinct graphs, identical
   keys yield the identical object.
3. Version bumped to 0.1.1 in both workspace packages.

## Success criteria

- [ ] `scripts/check.sh` passes fully (deps, complexity, lint, format,
      test, build); all existing tests stay green.
- [ ] The new regression tests fail when run against the unfixed
      `runner.py` (verify by stashing the fix or checking out the parent
      commit of the fix branch).
- [ ] No public API change: signatures of `compile` / `_compile_uncached`
      are unchanged.

## Tests

All new tests live in
`packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py`, appended
under a new class `TestCompileCacheKey`. They use the file's existing
helpers (`make_worker`, `make_chain`, `make_engine`) and need no new
fixtures. See step 2 for exact bodies.

## Branches and decision tree

This is a single-bugfix patch release. One branch, three sequential steps.
There is no parallelism to exploit: the test depends on knowing the fixed
signature (it doesn't change, but the failing-before check requires the fix
to exist as a diff), and the version bump should land last so CI validates
the final state.

```
branch fix/v0.1.1-compile-cache-key  (from main)
├── step 1  drop recomputation + redundant recheck   ── bottleneck for all below
├── step 2  regression tests                          (needs step 1)
└── step 3  version bump to 0.1.1                     (needs steps 1–2 green)
    → merge to main, tag v0.1.1
```

No other branches. If step 2's failing-before verification cannot be made
to fail on v0.1.0 code, stop: that means the test does not actually pin the
bug; revise step 2 before proceeding.

## Logical git commits

Conventional commits, one per step, in order:

1. `fix(engine): use caller-supplied cache key in _compile_uncached`
2. `test(engine): pin compile-cache separation across outer scopes`
3. `chore(release): bump version to 0.1.1`

## Steps

### Step 1 — Fix the cache key in `_compile_uncached`

Branch: `fix/v0.1.1-compile-cache-key`.

File: `packages/ngen-weave-core/src/ngen_weave/engine/runner.py`.

Current code (around line 462):

```python
    def _compile_uncached(
        self, wf: type[Workflow], models: dict, outer_scopes: tuple, key: tuple
    ) -> CompiledGraph:
        root_path = workflow_class_path(wf)
        key = (root_path, tuple(sorted(models.items())))
        cached = self._compiled.get(key)
        if cached is not None:
            return cached
```

Make these changes:

1. Delete the line `key = (root_path, tuple(sorted(models.items())))`.
2. Delete the two-line `cached = self._compiled.get(key)` /
   `if cached is not None: return cached` recheck. It is dead code:
   `compile()` is the only caller, has just missed on the same map under
   the same `_compiling` guard, and composite children recurse through
   `self.compile(...)`, never through `_compile_uncached` directly (see the
   `children = {...}` dict comprehension later in the same method).
3. Keep `root_path = workflow_class_path(wf)` — it is used below.
4. Update the method body so no comment narrates the deletion; the code
   should read as if the recheck never existed.

The resulting method signature stays exactly:

```python
def _compile_uncached(
    self, wf: type[Workflow], models: dict, outer_scopes: tuple, key: tuple
) -> CompiledGraph:
```

Out of scope for this step:

- Any change to `compile()`'s key computation or locking.
- Adding a lock around `self._compiled` (the `_compiling` set guard is
  sufficient for the sequential engine; concurrency hardening is not a
  v0.1.1 goal).
- Any new test (step 2).
- Refactoring the cache into its own class/module. Two dicts on `Engine`
  is the right size; an abstraction here would outlive its variation.

Verify:

```console
$ uv run pytest packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py -q
# expected: all pass (existing tests don't exercise cross-scope collisions)

$ uv run python -c "
import inspect, ngen_weave.engine.runner as r
src = inspect.getsource(r.Engine._compile_uncached)
assert 'tuple(sorted(models.items()))' not in src, 'recomputation still present'
assert src.count('self._compiled') == 1, 'redundant recheck still present'
print('ok')
"
# expected: ok
```

### Step 2 — Regression tests for cross-scope cache separation

Same branch, after step 1.

File: `packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py`.

Append at the end of the file:

```python
class TestCompileCacheKey:
    """Compile caching must key on outer scopes, not just class and bindings."""

    async def test_same_class_different_outer_scopes_get_distinct_graphs(self, tmp_path):
        leaf = make_worker("CacheLeaf", Root, Piece)
        middle = make_chain([leaf], Root, Piece)
        outer_a = make_chain([middle], Root, Piece)
        outer_b = make_chain([middle], Root, Piece)
        # Compile the SAME class twice under different enclosing scopes with
        # one shared models dict bound only on outer_a. Identical root and
        # bindings mean the buggy key (class + bindings, without
        # outer_scopes) collides on the second lookup; only the scope chain
        # differs between the two compilations.
        models = {workflow_class_path(outer_a): "slow"}
        engine, provider = make_engine(["{}"], tmp_path)
        graph_a = engine.compile(middle, models, outer_scopes=(outer_a,))
        graph_b = engine.compile(middle, models, outer_scopes=(outer_b,))
        assert graph_a is not graph_b
        assert graph_a.variants[workflow_class_path(leaf)] == "slow"
        assert graph_b.variants[workflow_class_path(leaf)] == "default"

    async def test_identical_compilation_returns_cached_object(self, tmp_path):
        leaf = make_worker("CacheLeaf2", Root, Piece)
        chain = make_chain([leaf], Root, Piece)
        engine, _ = make_engine(["{}"], tmp_path)
        models = {workflow_class_path(leaf): "fast"}
        first = engine.compile(chain, models)
        second = engine.compile(chain, models)
        assert first is second
```

Notes for the implementing agent:

- `graph.variants` maps each model-calling node's own class path within
  that graph to its resolved variant string (`wiring.nodes` keys are
  `workflow_class_path(node)`, no prefix); that is the observable that
  proves which cache entry was returned. Do not invent another probe.
- If the exact variant assertions fail because `resolve_model_variant`
  precedence differs from what's written here, do not adjust the test's
  intent: adjust the `models_a` / `models_b` dicts until the two
  compilations provably resolve different variants for the leaf, keeping
  the assertion `graph_a is not graph_b` intact. That identity assertion is
  the regression; the variant asserts document why.
- `make_worker` / `make_chain` register classes globally; the distinct
  names (`CacheLeaf`, `CacheLeaf2`) avoid registry collisions with other
  tests.

Out of scope for this step:

- Any change to `runner.py`. Step 1 owns that file.
- Testing thread-safety or concurrent `compile()` calls.
- An e2e run proving wrong checkpoints are produced on unfixed code; the
  unit-level identity assertion is sufficient and cheaper.

Verify:

```console

# expected: 2 passed

# then the stash pop restores the fix

# expected: all checks passed
```
