# v0.1.2 implementation plan

## Context

ngen-weave v0.1.x runs LangGraph workflows whose leaves call models through
`LiteLLMProvider` (litellm under the hood). Every transport exception today
becomes a retryable `InfraError`, so a missing API key burns three retries
and dies with a cryptic traceback; schema-invalid model replies take the
opposite path (`DataError`, no retry) and kill runs over one bad sample;
models.json authors must hand-write litellm provider prefixes.

Files touched:

- `packages/ngen-weave-core/src/ngen_weave/errors.py` — two new exception classes
- `packages/ngen-weave-core/src/ngen_weave/models/provider.py` — failure classification, log silencing
- `packages/ngen-weave-core/src/ngen_weave/models/registry.py` — `api` variant key, prefix composition
- `packages/ngen-weave-core/src/ngen_weave/schema_errors.py` — new module, friendly validation reports
- `packages/ngen-weave-core/src/ngen_weave/human.py` — completion message via the shared formatter
- `packages/ngen-weave-core/src/ngen_weave/engine/runner.py` — retry loop accepts `AgentReplyError`; `parse_output` / `parse_boolean` reclassification
- `packages/ngen-weave-cli/src/ngen_weave_cli/main.py` — friendly abort on invalid `-i` input
- `packages/ngen-weave-core/src/ngen_weave/models/test_provider.py`, `src/ngen_weave/test_schema_errors.py` (new), `src/ngen_weave/test_human.py`, `engine/test_engine.py`, `packages/ngen-weave-cli/tests/test_cli.py` — tests
- `packages/*/pyproject.toml` — version bump

Depends on: `../releases/v0.1.2.md` (requirements; read first). The error
taxonomy contract lives in `errors.py` docstrings; there is no `design/` doc
for the provider layer beyond what `registry.py` already documents.

## Goals

1. Deterministic provider failures (auth, model-not-found, connection) abort
   on the first attempt as non-retryable `ProviderError` with a message that
   names the variant and the likely fix. Litellm's stderr noise is silenced.
   Transient failures keep the existing retry policy unchanged.
2. `api` becomes a first-class variants.json key. The registry validates it
   against a known set and composes the litellm `model` prefix itself.
   Legacy prefixed `model` strings keep working.
3. Two validation regimes. User-supplied payloads (`run -i`, `resume -p`)
   hard-fail once with a field-by-field report. Model replies entering nodes
   fail as retryable `AgentReplyError`; after exhaustion the final message
   carries the field errors plus a reply excerpt.

## Success criteria

- [ ] All six test scenarios in `../releases/v0.1.2.md` pass (steps below
      implement them one-to-one).
- [ ] `scripts/check.sh` passes; no existing test changes intent.
- [ ] No signature change on any public function; the only new surface is
      `ProviderError`, `AgentReplyError`, `format_validation_error`, and the
      `api` models.json key.

## Tests

New tests land beside their code: registry and provider cases append to
`packages/ngen-weave-core/src/ngen_weave/models/test_provider.py`; the
formatter gets its own `packages/ngen-weave-core/src/ngen_weave/
test_schema_errors.py`; retry-count assertions go in
`packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py` using the
file's existing fake-provider helpers and the `asyncio.sleep` patch point
(`ngen_weave.engine.runner._sleep`); CLI abort cases go in
`packages/ngen-weave-cli/tests/test_cli.py` with typer's runner. Exact
assertions are specified per step.

## Branches and decision tree

Three branches. `feat/v0.1.2-provider-failures` starts first because its
step 1 defines the two exception classes every later step imports. The
formatter work in the second branch touches disjoint files and can start in
parallel immediately; only its retry step waits on the first branch.


### Step A1 — Error taxonomy additions

Branch: `feat/v0.1.2-provider-failures`.

File: `packages/ngen-weave-core/src/ngen_weave/errors.py`.

Append after `DataError`:

```python
class ProviderError(ConfigError):
    """Deterministic provider failure: auth rejected, unknown model or
    endpoint, unreachable host. Raised once at the completion boundary;
    retrying cannot help. The message names the variant and the fix."""


class AgentReplyError(NgWeaveError):
    """A model reply that fails its output schema. Retryable: one malformed
    sample must not kill a run when a re-ask may succeed. The message carries
    the schema violations and a truncated reply so exhaustion is diagnosable."""
```

Out of scope for this step:

- Any raiser of the new classes (steps A2 and B2).
- Changing the docstrings or behavior of the three existing classes.
- A common `Retryable` mixin or similar. Two flat classes match how the
  engine already dispatches on concrete types; a hierarchy here would
  outlive its variation.

### Step A2 — Classify permanent provider failures, silence litellm noise

Branch: `feat/v0.1.2-provider-failures`, after A1. Parallel with A3.

File: `packages/ngen-weave-core/src/ngen_weave/models/provider.py`.

The boundary already holds the raw litellm exception; classify there so
every future backend inherits the behavior by raising through the same
taxonomy.

1. Add a module-level table mapping exception types to fixed diagnosis
   text. Populate it lazily (litellm imports belong inside functions; see
   `LiteLLMProvider.complete`):

```python
def _permanent_failures() -> tuple[tuple[type[Exception], str], ...]:
    """Exception types retrying cannot fix, each with its diagnosis line."""
    import litellm.exceptions

    return (
        (
            litellm.exceptions.AuthenticationError,
            "authentication rejected by provider.\n"
            "Set the API key environment variable for this provider "
            "(see models.json), or point api_base at a local server "
            "(e.g. http://localhost:8080/v1).",
        ),
        (
            litellm.exceptions.NotFoundError,
            "model or endpoint not found.\n"
            "Check the model name and api_base for this variant in models.json.",
        ),
        (
            litellm.exceptions.APIConnectionError,
            "could not reach the provider endpoint.\n"
            "Check the network and api_base for this variant in models.json.",
        ),
    )
```

2. In `complete`, replace the blanket `except Exception` body with ordered
   handling: iterate `_permanent_failures()` first, matching with
   `isinstance(exc, cls)`; on a match raise
   `ProviderError(f"model call failed for variant {variant!r}: {diagnosis}")`
   from the original exception. Everything else keeps the existing
   `InfraError` wrap verbatim.

3. Silence litellm's own stderr logging so a failure prints once, from us.
   In `LiteLLMProvider.__init__`:

```python
import logging

_NOISY_LOGGERS = ("LiteLLM", "LiteLLM Router", "LiteLLM Proxy")

for name in _NOISY_LOGGERS:
    logger = logging.getLogger(name)
    logger.handlers.clear()
    logger.addHandler(logging.NullHandler())
    logger.propagate = False
```

with `_NOISY_LOGGERS` a module-level constant.

Out of scope for this step:

- Retrying inside the provider. The engine owns the retry policy; this step
  only decides whether an exception belongs in the retryable class.
- Timeout and rate-limit handling. They already fall through to `InfraError`
  untouched.
- Touching `registry.py` (step A3).
- Any engine change. `ProviderError` subclasses `ConfigError`, which the
  engine's retry loop never catches, so non-retryability falls out of the
  taxonomy without editing `runner.py`.

Tests, appended to `packages/ngen-weave-core/src/ngen_weave/models/
test_provider.py` in a new class `TestPermanentFailureClassification`,
using the file's existing `monkeypatch.setattr(litellm, "acompletion", ...)`
pattern (not marked live; no network):

- `AuthenticationError` raised by the stub surfaces as `ProviderError`;
  the message matches the variant name `'sonnet'` and contains
  `authentication rejected`.
- Same for `NotFoundError` and `APIConnectionError` (parametrize).
- A generic `RuntimeError` still raises `InfraError` (this duplicates the
  existing translation test; keep both so the class sits next to its new
  siblings).

Retry-count assertion lives in step B2's engine tests (release test 1 asks
for exactly zero attempts; that counter is patched in the engine suite).

Verify:

```console

# expected: all pass, including the new TestPermanentFailureClassification

$ scripts/check.sh
```

### Step A3 — `api` variant key with registry-side prefix composition

Branch: `feat/v0.1.2-provider-failures`, after A1. Parallel with A2.

File: `packages/ngen-weave-core/src/ngen_weave/models/registry.py`.

Hand-built `"openai/<name>"` strings caused the localhost launch failures
the release describes. Move the choice into data; the registry composes.

1. Module-level constant next to the imports:

```python
API_PREFIXES = {"openai-compatible": "openai/"}
```

One mapping entry per supported API dialect. Adding `anthropic` or `google`
later means adding one entry here, nothing else.

2. In `ModelRegistry.__init__`'s per-variant loop, after the `"model"` check,
   validate `api` when present:

```python
api = entry.get("api")
if api is not None and api not in API_PREFIXES:
    accepted = ", ".join(sorted(API_PREFIXES))
    raise ConfigError(
        f"{path}: variant {name!r} has unknown api {api!r}; accepted values: {accepted}"
    )
```

No error for the legacy case (no `api` key); bare names keep working unchanged.

3. In `kwargs()`, after `dict(entry)`:

```python
api = copy.pop("api", None)
prefix = API_PREFIXES.get(api) if api else None
if prefix and "/" not in copy["model"]:
    copy["model"] = prefix + copy["model"]
return copy
```

Rules locked here: an explicit `api` prefixes a bare model name; a `model`
value that already contains `/` is treated as legacy pre-prefixed and passes
through untouched; the `api` key is popped before the kwargs reach
litellm, which would reject an unknown keyword.

Out of scope for this step:

- New dialect entries (`anthropic`, `google`). The release says start with
  `openai-compatible`; the mapping exists so extension is one line, not so
  we guess prefixes untested today.
- Renaming `defaultVariant` or any other models.json surface.
- Updating README/docs examples to show the `api` form. That rides the
  release commit C1 where the docs get their release-pass read.

Tests, appended to `TestModelRegistry` in
`packages/ngen-weave-core/src/ngen_weave/models/test_provider.py`:

- A variant with `"api": "openai-compatible"` and bare `model` yields
  `kwargs()["model"] == "openai/<model>"` and carries no `api` key.
- A variant with `api` plus an already-prefixed model keeps the model
  string as written.
- A variant with no `api` and a prefixed model passes through unchanged
  (back-compat, matches the existing MODELS fixture).
- Unknown `api` value raises `ConfigError` matching the variant name and
  `accepted values`.

Verify:

### Step B1 — Shared friendly validation-error formatting

Branch: `feat/v0.1.2-schema-regimes`. Start any time; no dependency on
branch A.

New file: `packages/ngen-weave-core/src/ngen_weave/schema_errors.py`.

One function, used by every regime that reports pydantic failures to a
person:

```python
"""Friendly rendering of pydantic validation failures for people."""

from __future__ import annotations

from pydantic import BaseModel, ValidationError


def format_validation_error(model_type: type[BaseModel], exc: ValidationError) -> str:
    """Render exc as one `- field: message` line per violation.

    Field paths join nested locations with dots; the model name heads the
    block. This is the single formatting point for user-facing schema
    reports, whether the payload came from a person or a model.
    """
    lines = [f"{model_type.__name__}:"]
    for err in exc.errors(include_url=False):
        loc = ".".join(str(part) for part in err["loc"])
        lines.append(f"  - {loc}: {err['msg']}")
    return "\n".join(lines)
```

Then switch `validate_completion` in
`packages/ngen-weave-core/src/ngen_weave/human.py` to build its `DataError`
message from the formatter instead of stringifying the whole exception:

```python
raise DataError(
    f"review response does not match {format_validation_error(state_type, exc)}"
) from None
```

Drop the separate `missing` computation; `missing` violations arrive as
ordinary field lines now.

Future changes this absorbs: any new place a person sees schema errors
(the v0.2 HTTP API, the UI submission form) calls the same formatter, so a
report-format tweak lands in one file.

Out of scope for this step:

- Raising anything new from `validate_completion`; it stays `DataError`.
- CLI changes (B2).
- Handling `include_input` or truncating long values in the report; the
  default pydantic messages stay as-is until someone shows they don't read.

Tests, new file `packages/ngen-weave-core/src/ngen_weave/test_schema_errors.py`:

- A small model with an enum field and a required string; submit a wrong
  enum and omit the string; assert the rendered block has both lines, the
  dotted path for a nested location (use a second-level field via a list
  index, e.g. `items.0.name`), and the model name as the first line.
- Assert `include_url=False` kept `pydantic` URLs out of the output.

Also update any existing `test_human.py` assertion that matched the old
raw-exception message text so it asserts the field-line form instead; do
not weaken it to a substring-free existence check.

Verify:

### Step B2 — Two regimes: agent replies retry, user payloads abort

Branch: `feat/v0.1.2-schema-regimes`, after A1 is merged and B1 is done.
This step covers release tests 1, 2, 4, and 5.

Files:

- `packages/ngen-weave-core/src/ngen_weave/engine/runner.py`
- `packages/ngen-weave-cli/src/ngen_weave_cli/main.py`
- tests in `engine/test_engine.py` and `packages/ngen-weave-cli/tests/test_cli.py`

Engine side, `runner.py`:

1. Add a module constant near the top:

```python
REPLY_EXCERPT_CHARS = 500
```

2. Change `parse_output`: on final `ValidationError`, raise

```python
raise AgentReplyError(
    f"{node_path}: reply does not match "
    f"{format_validation_error(output_type, exc)}\n"
    f"last reply: {text[:REPLY_EXCERPT_CHARS]!r}"
) from None
```

Importing `AgentReplyError` from `ngen_weave.errors` and the formatter from
`ngen_weave.schema_errors`. Because the excerpt rides the exception message
itself, the exhausted-run report needs no extra machinery: the last raise
is what the run file records.

3. Change `parse_boolean` the same way: replace its `DataError` with
   `AgentReplyError(f"{node_path}: model reply {reply!r} is not a parseable "
   "boolean verdict\nlast reply: {reply[:REPLY_EXCERPT_CHARS]!r}")`. Booleans
   have no pydantic errors, so no formatter call; the excerpt is the point.

4. Widen the leaf retry loop in `_node_fn` from
   `except InfraError:` to `except (InfraError, AgentReplyError):`. Nothing
   else about the loop moves: same backoff formula, same provenance records,
   same `max_retries` bound. `DataError` stays outside the catch, so
   malformed *inputs*, router misses, and human-output mismatches keep
   failing fast.

CLI side, `main.py` in `run_command`:

5. Wrap the input validation:

```python
try:
    model = wf.input_type.model_validate(raw)
except ValidationError as exc:
    _fail(
        DataError(
            f"{input_file} does not match "
            f"{format_validation_error(wf.input_type, exc)}\n"
            "Fix the fields above and resubmit."
        )
    )
```

Importing `ValidationError` from pydantic, `DataError` from
`ngen_weave.errors`, the formatter from `ngen_weave.schema_errors`. The CLI
already prints `error: <message>` once and exits 1 on `NgWeaveError`, so
this is the whole mechanism. `resume -p` needs no change: `payload` flows
into `engine.resume`, which validates through `validate_completion`, now
formatted by B1, before any drive starts, so the abort happens once with no
retry records.

Out of scope for this step:

- Re-asking the model with an amended prompt on retry. The retry re-runs
  `_execute_leaf` with the identical prompt; smarter repair prompts are a
  feature, not a misclassification fix.
- Truncating or redacting the reply anywhere besides the excerpt length
  constant.
- Validating `-i` input against JSON Schema instead of pydantic. The model
  class is the single source of truth; a second validator would drift.
- An e2e bogus-key CLI test (release test 6 is marked optional; the unit
  classification tests in A2 cover the mechanism).

Tests:

In `packages/ngen-weave-core/src/ngen_weave/engine/test_engine.py`, using
existing helpers and `monkeypatch` on `ngen_weave.engine.runner._sleep` to
count backoff calls:

- Worker whose fake provider returns prose on every call while its
  `output_type` demands JSON fields: assert the run fails, the sleep stub
  fired `max_retries - 1` times (release test 4's attempt count), and
  `run_file.error["message"]` contains a field line and `last reply:`.
- Same setup returning valid JSON on the second call: assert the run
  completes and the metadata `iterations` for the node is 2.
- Control in model mode replying prose forever: assert failure with
  `not a parseable boolean` and the excerpt, retried the same number of
  times (release test 2's spirit applied to controls).
- Classification guard (release tests 1–2): fake provider raising
  `ProviderError("...")` directly; assert zero sleep-stub calls and the run
  file records one activation attempt. This pins non-retryability without
  importing litellm into the engine suite.

In `packages/ngen-weave-cli/tests/test_cli.py` (release test 5):

- `resume -p` with a response whose enum value is invalid against the
  waiting human's state: assert exit code 1, stderr containing
  `verdict:` and `Fix the fields above`, and the run file showing no
  record with status `retry` appended.
- `resume -p` missing a required field: assert exit 1 and the field name
  on stderr.
